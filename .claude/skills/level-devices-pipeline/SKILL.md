# 关卡系统与装置(时空战士)

标【定版】的是用户逐轮试玩拍板的规则,除非用户点名不要改。

## A. 碰撞总原则(一切装置的地基)

- **一切动态碰撞 = 原位更新 `scene.solids` 条目**:玩家/敌人/子弹/激光/敌人视线全部实时读 solids——平台移动只改 p.x/p.y,门开关只增删条目,全系统零额外碰撞代码自动跟随。Matter 静态体(尸体专用)需手动同步位置/增删。
- **oneWay 约定**:玩家/敌人只在"从上方落下"时着地(`prevY > s.y+1` 放行);水平不阻挡;**子弹与所有视线把 oneWay 当实体挡**(层板=掩体)。任何新射手的视线口径必须与弹道一致,否则出现"隔层锁定却打在桁架底面"(炮塔踩过)。
- 玩家新增移动能力全挂在 Player 两段碰撞里:台阶助步(X 段:着地迈上 ≤17px 落差+头顶净空检查)、穿层下落(Y 段:dropThroughUntil 窗口内放行全部 oneWay)。

## B. 移动平台(升降梯)

- level json 平台条目加 `move:{toX?,toY?,speed,pauseMs}` = 原点↔目标往返+端点驻留;只支持贴图类平台(oneWay 桁架/prop),graphics 画的动不了。
- 乘客判定=玩家脚底贴台顶 ±2px 且横向重叠 → **先带人后挪台**,玩家自身碰撞解算收尾;实测全程零漂移。
- **底停点=桁架底面落在地板线上**(台面高出地面 16px,小跳登台)——台面与地面齐平会让整个桁架嵌进地里(用户点名过)。顶停点=与目标楼层面齐平(走上走下无缝);中途层靠层板在井道留槽(±20px 缺口,胶囊 30 宽跨得过去)。
- 【坑】唤醒尸块只认"体心在台面之上"的真搭乘者(wakeRider)——大邻域唤醒会把井道附近地面尸体反复吵醒(抽搐回归的元凶之一)。
- 【坑】后台标签页 rAF 节流到 1-2Hz + dt 上限 0.05 → 平台看着只有 2px/s;**测运动系统必须先把游戏页 bringToFront**。

## C. 闸门 / 交互 / 检查点 / 存档

- 门 = solids 实体条目;开门 = splice 条目 + 删 Matter 体 + 门体绕顶 scaleY 收缩动画。**Phaser 4 WebGL 已移除 GeometryMask:setMask 是无声 no-op + 告警,收纳类动画只能用变换(scaleY/位移),不能用遮罩**。关门先查玩家占门洞(防夹死,160ms 延迟重试)。支持 `open:true` 初始开启。
- 门美术=侧棱三件(dev_gate_edge 门棱柱 45×200 / dev_gate_housing 门楣机构 / dev_gate_sill 门槛座);门上方隔墙=dev_wall_col(参考19)。**两轮返工教训:①挡路装置的出图必须明说"玩家看到的是侧棱/边缘,不是正脸"(正脸门框=贴在背景墙上的门,方向整个错);②结构件不能程序化凑合(样式化灰方块仍被点名"像没贴图的白模"),一律走切件管线**。
- 交互:InputState E 键按下沿;`consumeInteract()` **无论是否命中都消费**(防走廊里按过的 E 残留误触发);操作台必须配远距浮动信标(小装置在长走廊里没人看得见,用户点名过);locked 状态(拒绝音+锁定文案)+unlockConsole(解锁才亮信标=引导)。**操作台=走道后带,不碰撞(2026-07-22 用户终版:"它在过道旁边,人在过道中间走路",微俯视纵深读法;底座上移10px+接地影;推翻 07-17 的实体化——当时把"中空"点名理解成要实体,正解是后带纵深)**;E 距离交互不受影响。挡不挡路以"它在走道中央还是道旁"为准,不以体积为准。
- **子弹打动可推物**:Ballistics onHitWall 里对 `solid.pushable` 沿弹道 applyForce 于命中点(偏心=自然扭矩,打得挪打得转);气瓶同吃冲量再走 tank 伤害链。
- **冻尸支撑复核(每30帧)**:冻结时的支撑(电梯踏板/可推箱/气瓶/尸堆)事后移走会留"悬空静态尸"(用户点名电梯场景)——任一部件正下方 12px 内无实体且没压别的尸块=unfreeze 坠落重冻。载运不受影响(踏板即支撑)。
- 检查点:过点即存;SaveStore 三级降级(indexedDB→localStorage→内存,内存永远兜底写);BootScene 等存档读完经 registry 传给同步的 create。**选址铁律:重生后必须能自力恢复流程**——出口门外的死角=软锁雷区(用户实际被卡:存档恢复时封锁重置、门是关的、人在门外)。
- **玩家给的操作规则要逐字执行**:穿层下落定版=蹲态+**仍按住 S**+脚下 oneWay+**按 W**=穿层落下站立;松开 S 后按 W=原地起身跳;平地 S+W=蹲下起身跳。自作主张简化成"按住 S 即下落"返工过一轮。
- 跳跃 jumpVel 784【定版,+50%】满跳 159px。

## C2. junk 小件语义(minor:true,2026-07-23 定版,对标入侵者2 junk_* 的 maskBits-=COLLIDE_PLAYER)

- **solids 条目 `minor:true` = 桌面小物/飞行物级别的"junk 类"**:玩家/敌人**穿行**(X/Y/助步净空/起身净空全豁免)、**不挡** LOS/炮塔扫描锥、**不吃**贴身走位推;但**子弹可命中**(吃可推冲量)、**爆炸可掀**、Matter 体与世界正常互撞。当前:桌面电脑/监控双屏/显微镜(台面物独立件)+**泄漏乱窜的气瓶**(_startLeak 不再摘 solids,改打 minor——旧"整条摘除"=飞瓶对子弹隐形穿模;命中飞瓶=殉爆提前到 120ms)。
- **台面物独立化管线**:母本图 erase 挖掉台面物(渐变与椭圆同用绝对坐标,translate 后渐变锚偏=瓣全透明的坑同款要防)→ 台面物单独切件 → level 摆在家具顶面正上方(y 相接不重叠,严格不等式审计天然放行)→ pushable+minor。推桌它滑、翻桌它掉、中弹它飞——In2 的 junk_keyboard(独立 body,density0.7)是直接原型。
- **In2 道具物理量级锚点(反编译实测)**:轻塑料/杂物 density 0.3-0.7,常规木/金属 1-2,笨重金属 2-3;摩擦 0.5 默认/0.75 金属/0.8-0.9 木石;restitution 只给明确要弹的件,其余 0。
- **爆炸口径(与弹道/视线看齐)**:伤害与连锁全部过 segVsRect 遮挡(实心墙/闸门挡,pushable/oneWay/minor 不挡=门洞与格栅透爆压是特性);可推家具吃冲击波、breakable 按距离折伤、decor 抖 45ms×3、震屏随玩家距离 900px 线性衰减。

## D. 激光栅栏 / 可击破物 / 联动

- 激光:上(dev_laser_down 吊装)下(dev_laser_up 立地)发射柱间竖直光束;onMs/offMs/phase 周期;**亮起前 280ms 预热微光=公平预告**;光束三层辉光(宽晕+亮核+白热芯,ADD)带闪烁;只打玩家(机器人敌我识别,巡逻穿束合理);触束伤害的击退按行进反向定向(束心 sign(0)=0 不弹的边缘情况)。
- 可击破物(breakables):Ballistics 墙命中带 target 实体,**只吃玩家子弹**;打爆=熏黑+火花碎屑,残骸保留碰撞(仍是掩体);`laser.cabinet` 指向 breakable id=配电柜断电联动(战斗解 vs 操作解)。
- 【坑】自造测试弹丸必须给全 weapon 字段——漏 spreadDeg → `DegToRad(undefined)=NaN` 幽灵弹,永不命中也永不过期。

## E. 封锁房间战(LockdownRoom)

- **守军预置模型(用户定版"敌人不要凭空出现"):蜂巢守军=level enemies 里 `hive:true` 的常驻巡逻机器人,进关即在各层里**;LockdownRoom 不再刷兵,只管事件:triggerY/X 触发 → 锁门+全屏红光脉动+双音警报循环 → **全歼 hive 守军**=解锁操作台("⚠封锁中·残敌N")→ 按台=双门开+警报灭+存活炮塔断电垂头。炮塔常驻上电,与封锁状态无关(见 F)。
- 波次/刷兵预告/_pending 那套已随预置模型退役(历史坑存档:预告窗内 spawned 为空会误判清场=波次赛跑)。
- **封锁中死亡=开门重挂**(state→armed,门重开防锁死);守军是常驻单位——已击杀的保持死亡,重进接着上次战果打(不重置)。**cleared 阶段死亡同样必须重挂**(2026-07-22 workflow 审出):cleared 时 doorIn 仍关、炮塔仍上电、检查点全在门外——只处理 active 的死亡=清完守军被炮塔打死后永锁门外的软锁,godMode 试玩态掩盖着,关掉必现。"被当前配置掩盖"是一类要主动搜的 bug。
- 竞技场设计要点(调研定版):越过场中线才触发/进场一眼读全场/多路线用满空间(电梯+楼梯+箱跳)/层距铁律见 H。

## F. 壁挂炮塔(Turret)

- **扫描锥视野+常驻哨戒(用户三轮定版)**:炮塔进关即上电。探测域=**±9° 红色扇形锥**(13 条射线被墙/层板截断围成的多边形,半透明填充+边缘线——"一条红线扫不到人",范围性扫描是用户点名的模型);扇面扫过玩家胶囊=锁定(警报+灯闪+0.35s 前摇)→追瞄点射(扇面罩着人才开火);触不到超 1.2s 回扫掠。锁定态扇面更亮+中轴白热线。死亡/断电清扇面。
- **角度体系(穿模根治)**:全程用"相对外向水平的连续 rel 角"(朝右外向=0/朝左=π,不做 Wrap→朝左炮塔跨 π 不跳变);**机械限位 MOUNT_LIMIT=±80°**(扇区配置再宽也硬截,枪管永不翻进挂墙——旧版 pitch40±75=115° 极限角枪管插进挂臂,用户点名"内部穿模");扫掠界=[homeRel±sweep]∩±80°。**pitchDeg=扇区中心俯角**(挂高的炮塔必须往下压,否则罩不到走道="不识别",两次点名);**扇区落点必须复核不扫到必经门洞**(2612 台 pitch40+sweep75 时极限角正好打在 d_in 门洞地板上=玩家一进门被连发击退"根本进不去",收窄到 sweep35 后地板覆盖从 x≈2734 起,门洞安全、井口接近区照常侦测——配置完改必跑"站门洞 12s 不锁定"脚本)。
- 与 Enemy 鸭子类型兼容(alive/capsule/takeHit)直接进弹道目标列表;死亡=爆花+熏黑+垂枪残骸,不走 ragdoll 管线;封锁解除=存活炮塔 powerDown 垂头熄束(奖励感)。**capsule=基座∪枪管的实时渲染包围盒(getBounds 并集,2026-07-22 定版)**——手写小盒两次都低估(32×28 只罩转轴→"子弹穿机枪";按 1x 尺寸重写仍小一半,贴图实际按 2x 原生渲染):装置类敌人的命中框一律取真实渲染 bounds,枪转到哪判定到哪,换美术零维护。
- 基座+枪体两件切件(dev_turret_base/gun);转轴=基座铰接臂末端(切件实测占比 x0.83/y0.54);朝左=真角度+flipY+原点 y 镜像(与骨架瞄准件同约定)。

## G. 尸体安定(三轮返工的最终答案)

- 飞行/落地物理配方(见 character-anim-pipeline D 节)不变;**落地安定=静止即烘焙**:整具尸体全部件低速(speed<0.6/ang<0.12)持续 40 帧 → 全部转 isStatic(物理上不可能再动,还省求解器);鞭尸/断肢命中瞬间 unfreeze 恢复动力学 → 受力飞溅 → 自动再冻结;梯台搭载的冻尸经 wakeRider 解冻跟随。
- 【三轮教训】阻尼调参→强制入睡→烘焙:堆叠尸体的 resting-contact 让速度在 0.01↔0.4 永久振荡(求解器持续注能),碰撞级联又不断吵醒已睡邻居——**睡眠机制永远收不干净,"静止即静态"才是尸体留场的工程正解**。
- **【第四轮·根治】烘焙判据不能只看速度账面(2026-07-24,用户第四次点名"还是经常抽搐")**。实测根因:尸体挂在**停靠电梯的厢顶沿**上,肩甲嵌入静态板 9.9px,关节往下拽/板子往上顶=求解器每帧注能,该部件角速度被永久钉在 **0.19**——**比主动阻尼门限(<0.1)高、又永远达不到冻结门槛(<0.12)**,落进"既不被阻尼也永不冻结"的死区;而冻结是"全部件 AND",一条肢体卡住就否决整具 → 永久抽搐。现役**四道闸**(缺一不可):
  1. **位移窗口烘焙**(主judge,`_bakeIfPinned`):不问速度账面,只问"**它到底走没走**"——与参考位形比较,超容差就把参考跟进重新计时,容差内连续 N 帧就烤。两级:0.9s/4px 抓原地高频振动(转角按 26px/rad 折像素当量,实测卡住的肩甲振幅≈0.096rad≈2.5px,容差必须给到 4 才罩得住)、2.5s/12px 兜底"原地耗着"。真在滑/落/被载运的位移大,不会误冻(实测高速期零误冻)。
  2. **阻尼门限必须宽于冻结门槛**(0.5/0.1 → 1.2/0.45):否则必然存在死区,这是本轮病根的直接来源。
  3. **绝对兜底 5s**:从"最近一次进入动力学"起算(出生/解冻/中弹都重置,鞭尸不受影响),到点无条件烘焙——留场尸体的正确性排在物理纯洁性之前。专治"深嵌静态体被暴力弹射"(实测部件嵌入 16px、角速 6.4rad/step,位移窗口也抓不住因为它真的在乱动)。
  4. **支撑复核闭环**:间隔 30→**45 帧(必须 > 重冻延迟 40)**,否则一次误判=永久自激(解冻→没攒够 40 帧→又被解冻);且探针查不到支撑时先解冻验证一次,**解冻后没掉下去(<4px)就 latch 成"确有支撑"永不再查**(它是靠着结构的,只是探针几何够不着)。
  - 验收:12 个落点随机播撒 30 具 → 0 具卡死(改前电梯口一带约 1/3 卡死),中位 1.33s、最坏 4.98s;实弹全场击杀 @165fps → 5/5 在 0.56-0.65s 烘焙,之后 8s 内 55 个刚体累计路程 **0.000px**。
- 验收用**位移窗口法**:记录全部尸块位置,N 秒后看最大位移,0.00px 才算根治——"看起来不动"和内部 isSleeping 标志都不可信。**但它对"原地来回抖"是瞎的(净位移正好 0),必须同时量累计路程/逐帧位移**——三轮修复都"验收通过"而用户仍看得见抽搐,病根就在这个盲区(2026-07-24 血泪,详见 I 节)。
- **冻结前表面弹出守卫**(用户点名"尸体嵌进楼梯/地面"):_freeze 时体心若在任何 solid 内,抬到该实体顶面-4 再定格;**必须级联(≤4跳)**——被压死打进地里的尸块抬出地面后可能正落进叠在地面上的箱子里(实测踩过),单跳不干净。
- **每帧安定守卫(嵌地第二道闸)**:GibSystem.update 对每个非 static 尸块查体心是否在实体内,在则立即抬到顶面-5+泄纵向速度——不等冻结才修(高速穿隧/载具挤入/爆炸打入的当帧现形当帧修)。
- **电梯载尸=刚体平移法(入侵者2 对标定版)**:捕获以**躯干锚点**判定(根部件永不断落;"任一部件在窗内就整具带走"曾把半搭井槽沿的尸体拖着穿多层楼——用户实见;部件均值锚会被飞远断肢拉偏),躯干在厢体足印内才收编;全部件随厢 setPosition 刚性平移(冻结尸原样搬运=零物理噪声);**平移中逐帧刮离检测**:任一部件将进非电梯实体=整具唤醒释放留层(与"井槽沿刮下"同一语义,冻结尸也适用——static 体 setPosition 无碰撞响应,不检测就是鬼穿)。旧"大邻域唤醒再靠物理推"=掉埋事故元凶,已退役。**下行贴底挤尸窗口只留一个厢底厚度(~22px)**——开到 70 会在下行途中把足印下方全部尸块提前扫飞,载运就没得载(实测踩过)。搭在井槽沿上的尸块被楼板刮下留层=正确行为。**下行厢底扫过站定玩家=砸一下**(非致命 hurt+闷响+击退,每次下行一次;落定平层后人站厢内=用户定版"被砸到但最终能进电梯";致命挤压归厢顶 crush)。**乘客必须豁免砸判与压判**:rider 先随厢位移后,旧厢底 y 对新玩家 y 的几何恒判"被扫过"=下行第一帧必误砸乘客(用户实见"下行莫名受击");豁免用**位移前预存的 riding 布尔**,勿在判定处重算(乘客已被挪过 ndy,±2px 容差必失效);压判同加(净高对站姿仅 ~4.7px 裕量,一帧吸附抖动=9999 秒杀)。

## I. 验收方法论(持续追加)

- **测试标准 harness(每次自动化测试第一个 evaluate 就装上,治本会话四类反复踩的坑)**:
```js
window.__h = (() => {
  const s = window.__tw.scene, loop = s.game.loop
  const tp = (x, y) => { // 传送+嵌固断言(传送点嵌进家具=三轮"神秘瞬移/冻结"假象的元凶)
    window.__tw.teleport(x, y); s.player.vx = 0; s.player.vy = 0
    const c = s.player.capsule
    const hit = s.solids.find(o => !o.oneWay && c.x < o.x + o.w && c.x + c.w > o.x && c.y < o.y + o.h && c.y + c.h > o.y)
    if (hit) throw new Error('tp 嵌固: ' + JSON.stringify({ x, y, hit: { x: hit.x, y: hit.y, w: hit.w, h: hit.h, prop: hit.prop } }))
  }
  const env = async () => { // 时钟模式探测:前台=真实rAF(泵帧无效),遮挡节流=只能泵帧
    const n = await new Promise(r => { let k = 0; const t0 = performance.now()
      const f = () => { k++; performance.now() - t0 < 400 ? requestAnimationFrame(f) : r(k * 2.5) }; requestAnimationFrame(f) })
    return { raf: Math.round(n), mode: n > 50 ? 'realtime' : 'pump' } // realtime→用 wait;pump→用 loop.step,且计时断言不可用真实 ms
  }
  const reset = () => { // 场地复位:多轮混沌测试间不复位=下一轮全在被污染的场上踩假坑
    s.player.invulnUntil = s.time.now + 9e9
    if (s.lockdown) s.lockdown.state = 'done'
    for (const p of s._pushables) if (p._body) { s.matter.body.setPosition(p._body, { x: p._ox0 ?? p._body.position.x, y: p._body.position.y }); }
  }
  const pump = (n) => { let t = loop.now; for (let i = 0; i < n; i++) { t += 16.7; loop.step(t) } }
  return { tp, env, reset, pump }
})()
```
- **【物理测试的根本前提】Matter 锁真实时间,泵帧根本推不动物理**(2026-07-24 实测):Phaser 4 的 Matter World 是**时间累加器+固定 16.667ms 步长**(`world.runner.delta=16.667`/`timeBuffer`),引擎步数由**真实墙钟**决定,与泵帧完全解耦。实测泵 120 帧(名义 2s)物理只推进 933ms=脚本真实耗时。**推论:①一切物理相关的时序验收都不能用泵帧(尸体安定耗时/气瓶飞行/推箱手感全部失真)②要测物理只能用真实 rAF 跑真实秒数**(`await new Promise(r=>requestAnimationFrame(r))` 循环);**验证物理确实在走用 `matter.world.engine.timing.timestamp` 对比墙钟(比值≈1 才算真在跑)**。泵帧仍适用于纯逻辑/运动学(玩家/敌人/装置状态机)。
- **【由此而来的代码铁律】给刚体施力/阻尼必须按时间归一化**:引擎步锁 60Hz、每步末清空 force,而 `applyForce` 是**每渲染帧**调一次——165Hz 屏上每物理步攒 2.75 帧的力=**2.75 倍推力**(30Hz 屏则不足 1 倍)。凡"每帧 applyForce/衰减/计数"一律 `×(dt*60)` 或 `Math.pow(k, dt*60)`,窗口计时一律**用毫秒不用帧数**;否则手感随玩家显示器刷新率漂移,而且**你在 60fps 下调好的配平在实机上根本不成立**(气瓶"平均推力<重力"就这么失效过)。
- **净位移 ≠ 静止:振动类缺陷必须量"累计路程"**(2026-07-24,尸体抽搐第四轮的方法论病根):位移窗口法只能证明"没漂走",而抽搐是**原地来回抖,净位移恰好 0.00px**——三轮修复靠它"验收通过",用户却一直看得见。**判定"真静止"必须逐帧累加 `|pos-prevPos|` 求路程(顺便记 maxStep),路程 0.00 才算真不动**;想归因还要包裹状态迁移函数记事件+`new Error().stack` 抓调用来源(本轮就是靠它抓到"支撑复核在偷偷解冻")。同理适用:抖动的 UI、颤动的特效、来回弹的碰撞解算。
- **物理疑难先看真实接触对,别靠猜**:`matter.world.engine.pairs.list.filter(p=>p.isActive)` 直接给出"谁在碰谁、穿透多深"——本轮几十分钟的假设全被一句 `pauldron×static depth=9.9` 终结(定位到停靠电梯的厢顶沿)。配合 `body.speed/angularSpeed` 逐部件排名,3 分钟锁定元凶部件。
- **复现不出来时先怀疑"测试条件与实机不同"**:本轮先后排除了泵帧步长(60 vs 165fps 都测)、尸堆、楼梯/格栅/家具落点、火拼实战——最后是**落点靠近停靠电梯**才复现。系统性布点审计(把同一具尸体扔到 N 类落点各泡一遍)比反复猜快得多。
- **测试场地必须先扫遮挡,别信"看着挺空"**(2026-07-25 连栽三次:实弹打可推物 hits=0,以为弹道有 bug,实为①发射点 x2640 落在井壁 2600-2645 **内部**、②目标传送到 2900 而 x2740 有掩体箱挡住、③多次测试把好几件家具都传送到同一点堆成一堆)。定式=开测前对射线路径跑一遍 `segVsRect` 列出全部 blockers 并按 t 排序打印;多轮测试之间**把所有可推物按 `_lastGood` 归位**(场地污染会让下一轮全在踩假坑)。
- **帧率崩了先量 rAF 再下结论**:同一段测量在 2Hz 与 165Hz 下能给出**完全相反**的数值(弹着冲量测出来差 7 倍),而 `visibilityState/hasFocus` 全是正常值骗不出来。定式=每轮时序测量前先量 1s rAF;掉速就用 PowerShell `SetForegroundWindow` 把"时空战士"窗口拉回前台(本轮实测 setFg=True 后 2Hz→165Hz 立即恢复),恢复后**整轮重测**,别拿掉速期的数字调参。
- **测速断言先确认跑道净空**:两小时追过一个不存在的"推速被钉在137px/s"——三次测得全是"跑道到障碍物的长度÷时间"(272px 跑道尽头有掩体箱)。测位移前列出路径上的 solids。
