# 关卡系统与装置(时空战士)

标【定版】的是用户逐轮试玩拍板的规则,除非用户点名不要改。

## A. 碰撞总原则(一切装置的地基)

- **一切动态碰撞 = 原位更新 `scene.solids` 条目**:玩家/敌人/子弹/激光/敌人视线全部实时读 solids——平台移动只改 p.x/p.y,门开关只增删条目,全系统零额外碰撞代码自动跟随。Matter 静态体(尸体专用)需手动同步位置/增删。
- **oneWay 约定**:玩家/敌人只在"从上方落下"时着地(`prevY > s.y+1` 放行);水平不阻挡;**子弹与所有视线把 oneWay 当实体挡**(层板=掩体)。任何新射手的视线口径必须与弹道一致,否则出现"隔层锁定却打在桁架底面"(炮塔踩过)。
- 玩家新增移动能力全挂在 Player 两段碰撞里:台阶助步(X 段:着地迈上 ≤17px 落差+头顶净空检查)、穿层下落(Y 段:dropThroughUntil 窗口内放行全部 oneWay)。

## B. 移动平台(升降梯)

- level json 平台条目加 `move:{toX?,toY?,speed,pauseMs}` = 原点↔目标往返+端点驻留;只支持贴图类平台(oneWay 桁架/prop),graphics 画的动不了。
- 乘客判定=玩家脚底贴台顶 ±2px 且横向重叠 → **先带人后挪台**,玩家自身碰撞解算收尾;实测全程零漂移。
- **底停点=桁架底面落在地板线上**(台面高出地面 16px,小跳登台)——台面与地面齐平会让整个桁架嵌进地里(用户点名过)。顶停点=与目标楼层面齐平(走上走下无缝);中途层靠层板在井道留槽(±20px 缺口,胶囊 30 宽跨得过去)。
- 【坑】唤醒尸块只认"体心在台面之上"的真搭乘者(wakeRider)——大邻域唤醒会把井道附近地面尸体反复吵醒(抽搐回归的元凶之一)。
- 【坑】后台标签页 rAF 节流到 1-2Hz + dt 上限 0.05 → 平台看着只有 2px/s;**测运动系统必须先把游戏页 bringToFront**。

## C. 闸门 / 交互 / 检查点 / 存档

- 门 = solids 实体条目;开门 = splice 条目 + 删 Matter 体 + 门体绕顶 scaleY 收缩动画。**Phaser 4 WebGL 已移除 GeometryMask:setMask 是无声 no-op + 告警,收纳类动画只能用变换(scaleY/位移),不能用遮罩**。关门先查玩家占门洞(防夹死,160ms 延迟重试)。支持 `open:true` 初始开启。
- 门美术=侧棱三件(dev_gate_edge 门棱柱 45×200 / dev_gate_housing 门楣机构 / dev_gate_sill 门槛座);门上方隔墙=dev_wall_col(参考19)。**两轮返工教训:①挡路装置的出图必须明说"玩家看到的是侧棱/边缘,不是正脸"(正脸门框=贴在背景墙上的门,方向整个错);②结构件不能程序化凑合(样式化灰方块仍被点名"像没贴图的白模"),一律走切件管线**。
- 交互:InputState E 键按下沿;`consumeInteract()` **无论是否命中都消费**(防走廊里按过的 E 残留误触发);操作台必须配远距浮动信标(小装置在长走廊里没人看得见,用户点名过);locked 状态(拒绝音+锁定文案)+unlockConsole(解锁才亮信标=引导)。
- 检查点:过点即存;SaveStore 三级降级(indexedDB→localStorage→内存,内存永远兜底写);BootScene 等存档读完经 registry 传给同步的 create。**选址铁律:重生后必须能自力恢复流程**——出口门外的死角=软锁雷区(用户实际被卡:存档恢复时封锁重置、门是关的、人在门外)。
- **玩家给的操作规则要逐字执行**:穿层下落定版=蹲态+**仍按住 S**+脚下 oneWay+**按 W**=穿层落下站立;松开 S 后按 W=原地起身跳;平地 S+W=蹲下起身跳。自作主张简化成"按住 S 即下落"返工过一轮。
- 跳跃 jumpVel 784【定版,+50%】满跳 159px。

## D. 激光栅栏 / 可击破物 / 联动

- 激光:上(dev_laser_down 吊装)下(dev_laser_up 立地)发射柱间竖直光束;onMs/offMs/phase 周期;**亮起前 280ms 预热微光=公平预告**;光束三层辉光(宽晕+亮核+白热芯,ADD)带闪烁;只打玩家(机器人敌我识别,巡逻穿束合理);触束伤害的击退按行进反向定向(束心 sign(0)=0 不弹的边缘情况)。
- 可击破物(breakables):Ballistics 墙命中带 target 实体,**只吃玩家子弹**;打爆=熏黑+火花碎屑,残骸保留碰撞(仍是掩体);`laser.cabinet` 指向 breakable id=配电柜断电联动(战斗解 vs 操作解)。
- 【坑】自造测试弹丸必须给全 weapon 字段——漏 spreadDeg → `DegToRad(undefined)=NaN` 幽灵弹,永不命中也永不过期。

## E. 封锁房间战(LockdownRoom)

- **守军预置模型(用户定版"敌人不要凭空出现"):蜂巢守军=level enemies 里 `hive:true` 的常驻巡逻机器人,进关即在各层里**;LockdownRoom 不再刷兵,只管事件:triggerY/X 触发 → 锁门+全屏红光脉动+双音警报循环 → **全歼 hive 守军**=解锁操作台("⚠封锁中·残敌N")→ 按台=双门开+警报灭+存活炮塔断电垂头。炮塔常驻上电,与封锁状态无关(见 F)。
- 波次/刷兵预告/_pending 那套已随预置模型退役(历史坑存档:预告窗内 spawned 为空会误判清场=波次赛跑)。
- **封锁中死亡=开门重挂**(state→armed,门重开防锁死);守军是常驻单位——已击杀的保持死亡,重进接着上次战果打(不重置)。
- 竞技场设计要点(调研定版):越过场中线才触发/进场一眼读全场/多路线用满空间(电梯+楼梯+箱跳)/层距铁律见 H。

## F. 壁挂炮塔(Turret)

- **扫描锥视野+常驻哨戒(用户三轮定版)**:炮塔进关即上电。探测域=**±9° 红色扇形锥**(13 条射线被墙/层板截断围成的多边形,半透明填充+边缘线——"一条红线扫不到人",范围性扫描是用户点名的模型);扇面扫过玩家胶囊=锁定(警报+灯闪+0.35s 前摇)→追瞄点射(扇面罩着人才开火);触不到超 1.2s 回扫掠。锁定态扇面更亮+中轴白热线。死亡/断电清扇面。
- **角度体系(穿模根治)**:全程用"相对外向水平的连续 rel 角"(朝右外向=0/朝左=π,不做 Wrap→朝左炮塔跨 π 不跳变);**机械限位 MOUNT_LIMIT=±80°**(扇区配置再宽也硬截,枪管永不翻进挂墙——旧版 pitch40±75=115° 极限角枪管插进挂臂,用户点名"内部穿模");扫掠界=[homeRel±sweep]∩±80°。**pitchDeg=扇区中心俯角**(挂高的炮塔必须往下压,否则罩不到走道="不识别",两次点名);**扇区落点必须复核不扫到必经门洞**(2612 台 pitch40+sweep75 时极限角正好打在 d_in 门洞地板上=玩家一进门被连发击退"根本进不去",收窄到 sweep35 后地板覆盖从 x≈2734 起,门洞安全、井口接近区照常侦测——配置完改必跑"站门洞 12s 不锁定"脚本)。
- 与 Enemy 鸭子类型兼容(alive/capsule/takeHit)直接进弹道目标列表;死亡=爆花+熏黑+垂枪残骸,不走 ragdoll 管线;封锁解除=存活炮塔 powerDown 垂头熄束(奖励感)。
- 基座+枪体两件切件(dev_turret_base/gun);转轴=基座铰接臂末端(切件实测占比 x0.83/y0.54);朝左=真角度+flipY+原点 y 镜像(与骨架瞄准件同约定)。

## G. 尸体安定(三轮返工的最终答案)

- 飞行/落地物理配方(见 character-anim-pipeline D 节)不变;**落地安定=静止即烘焙**:整具尸体全部件低速(speed<0.6/ang<0.12)持续 40 帧 → 全部转 isStatic(物理上不可能再动,还省求解器);鞭尸/断肢命中瞬间 unfreeze 恢复动力学 → 受力飞溅 → 自动再冻结;梯台搭载的冻尸经 wakeRider 解冻跟随。
- 【三轮教训】阻尼调参→强制入睡→烘焙:堆叠尸体的 resting-contact 让速度在 0.01↔0.4 永久振荡(求解器持续注能),碰撞级联又不断吵醒已睡邻居——**睡眠机制永远收不干净,"静止即静态"才是尸体留场的工程正解**。低速主动阻尼(speed<0.5 时每帧 ×0.5)保留用于加速收敛到冻结门槛。
- 验收用**位移窗口法**:记录全部尸块位置,N 秒后看最大位移,0.00px 才算根治——"看起来不动"和内部 isSleeping 标志都不可信。
- **冻结前表面弹出守卫**(用户点名"尸体嵌进楼梯/地面"):_freeze 时体心若在任何 solid 内,抬到该实体顶面-4 再定格;**必须级联(≤4跳)**——被压死打进地里的尸块抬出地面后可能正落进叠在地面上的箱子里(实测踩过),单跳不干净。
- **每帧安定守卫(嵌地第二道闸)**:GibSystem.update 对每个非 static 尸块查体心是否在实体内,在则立即抬到顶面-5+泄纵向速度——不等冻结才修(高速穿隧/载具挤入/爆炸打入的当帧现形当帧修)。
- **电梯载尸=刚体平移法(入侵者2 对标定版)**:厢底/厢顶载运窗内有任一部件的整具尸体,全部件随厢 setPosition 刚性平移(冻结尸保持冻结原样搬运=零物理噪声;醒着的同时对齐纵向速度)。旧"大邻域唤醒再靠物理推"=掉埋事故元凶,已退役。**下行贴底挤尸窗口只留一个厢底厚度(~22px)**——开到 70 会在下行途中把足印下方全部尸块提前扫飞,载运就没得载(实测踩过)。搭在井槽沿上的尸块被楼板刮下留层=正确行为。**下行厢底扫过站定玩家=砸一下**(非致命 hurt+闷响+击退,每次下行一次;落定平层后人站厢内=用户定版"被砸到但最终能进电梯";致命挤压归厢顶 crush)。
- **【Matter 0.19 大坑】setVelocity 对"久睡初醒"的刚体可能只改速度账面**(positionPrev 不按正确 delta 回写),读回速度有值但位置积分≈0——冲量类效果(推动/爆炸波/挤出)一律 **applyForce**(走引擎积分永远有效,气瓶飞行即此路径);setVelocity 只用于"对齐已有运动"(如载运时同步 vy)。
- **可推物三防(用户实际踩中"推桌进角落被挤穿墙掉出世界"后的定版)**:①solid AABB 从刚体**顶点**算,禁用 body.bounds(它含速度扩张,推挤抖动时盒子凭空胀大吞掉贴身玩家);②玩家 X 段对 pushable 深重叠=**朝渗透浅侧温和排出**(vx=0 也解算=家具能推人;禁止按速度方向深弹——角落里会把人从家具另一侧瞬移穿墙坠入墙缝);③Y 段落地吸附对 pushable 加 prevY>s.y+12 守卫(防翻倾盒把旁人铲上顶)。**世界底安全网**:y>世界高+160 → player.die() 重生(不吃血量,godMode 生效)——未知异常出界的最后兜底,必须常在。
- **测试假象:窗口前台时泵帧不推进时钟**——真实 rAF 与 loop.step 混跑,泵帧的合成时间戳落在真实时间之后/之前被钳制,`time.now` 实际由真实帧推进;前台环境下计时类断言(引信/发车延时)用真实 wait,别数泵帧。

## H. 楼梯与多层结构

- **楼梯=双斜梁开放式钢梯(反馈批定版,用户点名"现实台阶下面没东西"):碰撞=每级一块薄踏板(h8,顶面坐标与旧实心柱一致=助步/穿洞几何零回归),踏板之间和梯下全空——楼下可钻(高段立走/低段蹲爬,天然战术口袋),子弹可从梯下穿过**;视觉=_buildStairs 拼装参考23 套件:斜梁(母本自带15.6°倾角,切件 rotate 转平+insetX 裁斜切口,游戏内按坡度旋转 tileSprite 平铺于踏步后)+逐级格栅踏步切件+管扶手(立柱切件每4级+双横管 graphics,走道后带不碰撞画在人物后)+底部锚固板。玩家台阶助步(≤17px)照常爬;机器人无助步=楼梯仍是玩家专属路线;**刷兵点勿放楼梯区**。
- **层距铁律 ≥150**:站姿垂直上瞄枪口离脚 129px、蹲姿 104px——层距 104 时枪身穿层、子弹能打到楼上(用户点名);150 同时=新跳高恰可直跳上层(升降梯降级为舒适路线,符合多路线原则)。
- **【多轮返工定论】整层楼梯楔的几何铁律**:stairs 展开是"实心三角楔"(柱体从踏面直通基面 st.y),由此三个死局全部实测/推演确认——①同井道 zigzag:上段楔的基面=横贯井道的天花板,下段爬升头部必撞;②相邻层换向(含着陆台变体):换向喉部两楔必然共享空域;③各层错开 x 直跑串联:每段的高墙侧挡死本层通路,永远到不了下一段的矮端。**定版:整层楼梯每关最多一段、独占 x 跨度、上层楼板开洞;多层垂直主干=电梯厢×2+格栅速降链**(蜂巢 QZ-03:主梯地表↔B4 暗门门控、副梯 B1↔B4、大楼梯 B4↔B3、格栅链每层)。
- **楼板洞沿余量**:楼梯穿洞处,洞沿到"头部开始越过楼板底面的那级台阶"要按**迈步前胶囊位置**留余量(≥ 台阶面 x ± 胶囊全宽 30 + 3px)——只按台阶自身算会在洞沿差 15-20px 卡死(实测三次)。
- **盲跳陷阱禁令**:井口/楼板洞边缘 ~250px 内不放挡路道具——被挡触发的跳跃惯性直接把人送进坑(B3 掩体箱距井 70px=跳箱坠井,已挪)。
- **井口暗门(v4 定版,三轮点名的最终答案:"地面=有厚度的钢甲板,板下有夹层;门收进地下结构,而且结构必须画出来")**:顶视带 [454..500]=井坑 dev_hatch_pit(框环+井内壁,构造性对齐:井洞 frac 0.074..0.942/中心 0.508/口沿顶 0.083)+厚滑板×2(闭合平嵌框环;开启 x 平移入舱,框沿留 ~6px 残留板缘)+**收纳舱检修盖板 dev_hatch_lid(可见的机器盖板,滑板从其下钻入)**;**剖面带 [486..544](走道前立面=切开的甲板)=dev_hatch_xsec(甲板切断面+剖开的收纳舱空腔,内壁/导轨座可见)+dev_hatch_sub(空腔下支撑斜撑板)+dev_hatch_slab(滑板侧面断面条,与顶视滑板同 tween 平移——开门时在断面里亲眼看到滑板滑进舱内,闭合时它封住井道断面)**。断面条与顶视板加进同一 leaves 数组即同步。教训链:v1 原位裁切缩叶=贴图级❌ / v2 露天滑轨=门板裸在地面上动❌ / v3 隐形裁切盖板=地下结构不可见"像画在矩形上"❌ / **v4 把结构本身画出来=✓——"收进地下"必须是可见事实,不是遮挡把戏**。配 afterDoor 电梯门控。

## I. 验收方法论(持续追加)

- **泵帧时间锚点用 `game.loop.now`**(`let t = game.loop.now; loop.step(t += 16.7)`),不要每次 evaluate 都从 performance.now() 起——长测试把 loop 内部时钟推到"未来"后,新锚点在过去,delta 掉到 1-3ms:走路慢数倍、tween 几乎不动、"卡死"全是假象(真实 rAF 玩起来没事)。
- **窗口遮挡节流(比后台标签页更阴)**:Chrome 窗口被其他窗口盖住时 rAF 掉到 1-2Hz,而 `document.visibilityState==='visible' && hasFocus()===true` 仍然全真——症状=运动系统慢几十倍(电梯 13px/s、炮塔转不动),同会话内已两次误判成代码 bug。**每段时序敏感测试前先量 1s 真实 rAF 数;掉速就用 PowerShell SetForegroundWindow 把"时空战士"窗口拉回前台**(附着模式下 MCP 的 select_page 不会抬升 OS 窗口)。
- **脚本翻障碍=队列跳+按住**:置 jumpQueuedAt 的同时 jumpHeld 保持 ~400ms,否则松键截断变 31px 小跳翻不过箱子(曾误判为关卡缺陷);被挡检测(lastX 不动且 grounded)触发。等电梯/停靠窗类交互:**先站到位再等**,停靠窗(~1.2s)不够边走边赶。
- 交互模拟:E=覆写 `input2.consumeInteract=()=>true` 泵 1 帧再还原(场景层每帧只消费一次)。

- **测试期玩家无敌**:`player.invulnUntil = now + 9e9`——防测试中被打死触发死亡重置/重生搅乱脚本(被机器人巡逻圈杀过多次)。
- 输入钉住:包裹 `input2.update` 后覆写持续字段(crouchHeld/jumpHeld/moveX/aimX);边沿字段(crouchPressed/jumpQueuedAt/interactPressed)直接赋值即可。测完还原。
- 行为验证优先"状态采样进数组"(定期 push 坐标/状态/标志),截图只用来看观感;相机操作记得 stopFollow→测完 startFollow(camTarget)。
- 封锁/波次类流程用 killAll 快进;时序相关(激光相位/电梯到站)用轮询到目标状态再 `game.loop.sleep()` 冻结拍照。
