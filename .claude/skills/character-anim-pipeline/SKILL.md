# 角色模型与动作管线(时空战士)

一切参数都是用户逐轮试玩拍板的**定版**。标了【勿改】的,除非用户本人点名,不要动;调其他参数前先理解它所在的约束关系(很多参数互相锁定)。

## A. 角色美术管线(母本 → 部件)

**流程**: ChatGPT 出母本 → 按文件ID下载原图 → 切件脚本 → rigs.json → 泵帧验收。全程 ~30 分钟/角色。

1. **出图**(Claude 直驱 ChatGPT 打字,用户只拍板审美):
   - 配方:首句锁死配色(如"深灰机械人形+橙色能量灯")+ 持枪战斗姿态或立正直腿 + **严格正侧面朝右全身**(头顶到脚底都在画面内)+ 浅灰瓷砖背景 + 无文字无水印。
   - 立正直腿姿势对切件最友好(无烘焙弯曲,角度全交给骨架);关节处有发光核心的设计=天然 J 表标记点。
   - 坑:同会话"同一个角色"指代不可靠,必须首条 prompt 完整锁配色;卡在"最后微调"刷新页面即可拿图。
2. **下载原图**:
   - 坑:会话含多张历史图,DOM 虚拟列表下 `find(img)` 会抓到旧图。**先滚到会话真底部(循环 scrollTop=scrollHeight 直到 scrollHeight 稳定),再按文件 ID 精确匹配**。
   - 签名 URL 无法 curl,用页面内 fetch→base64,经 evaluate 的 filePath 参数落盘,node 解码。
3. **单源铁律【勿改】**: 主体所有部件从同一张母本切(多母本拼装身材必然失调);跨源仅限无法生成的姿态件(用 pivotJoint/parentJoint 分离挂接)。
4. **切件脚本**(模板:tools/cut-player.mjs、cut-robot.mjs、cut-props.mjs 道具无关节版):
   - J 表声明关节**一次**,部件 pivot 与父件 attach 由同一源点经各自变换自动换算——对齐由构造保证,**禁止手工测量**。
   - 部件多边形在关节处伸出**圆帽重叠区**(~40px 源图),任意旋转不露缝。
   - 背景去除=从多边形边界**泛洪**(lum>0.55 且 sat<0.3 判亮背景),装甲内部高光不会被打穿;"只保留最大连通块"除尘。
   - `vert:[a,b]`=腿旋转到髋→膝垂直;`horiz:[a,b]`=枪管归平(轴取纯枪管段)。**坑:horiz 的消偏方向与 vert 相反**(deg 乘 -1),自检(旋转后 dy<1.5px)会抓住符号错。
   - 流程:preview 模式画红线人眼校版(1-2轮)→ final 自动打印可直接抄的 rigs 数据。
   - **禁区【勿改】**: 多边形勿越母本基座沿(soleY 之下全是暗色基座,泛洪清不掉→切件底部出现全宽黑板,曾把脚拉长 25%);水印区绝对避开。
5. **十部件结构**: 头 / 躯干(root,胸前烤臂影=抬枪露完整胸甲) / 固定肩甲(z11 盖住肩关节,手臂从其下转出,否则"贴纸感") / 大臂(aim,aimFactor 0.55) / armgun(小臂+双手+枪一体,换枪=换整图,muzzle 点) / 前后大小腿 / 前后脚掌(**真踝关节**,防"脚掌朝上"类问题)。后腿三件=前腿 darken 0.8 副本(copyFrom)。
6. **z 序**: 后腿 3-4 < 躯干 5 < 头 6 < 前腿 7-8 < armgun 9 < 大臂 10 < 肩甲 11。

## B. 骨架铁律(rigs.json / CharacterRig.js)

- **【坐标系铁律】rigs.json 的 size/pivot/attach/muzzle 一律是"世界尺寸(1x)",而贴图是 2x**(CharacterRig 统一 `setScale(0.5)`)。**验收公式:贴图宽 ÷ size[0] 必须 ≈ 2**(现役 rifle 133/67=1.99、torso 95/48=1.98、robot_armgun 97/49=1.98)。**新切件脚本必须自己折算 ×0.5 再写进 rigs.json**——`cut-armguns.mjs` 2026-07-25 把 2x 贴图像素原样打印,三把新枪比值全是 1.00,后果=`getMuzzle()` 的 `(muzzle-pivot)` 被当世界偏移用,**枪口点飞到真炮口外整整一倍远**(大炮偏 52px),用户点名"新武器的枪口火焰离枪口太远"。注意 origin 用的是 `pivot/size` 比例、显示尺寸用的是 `texW×0.5`,两者都对倍数不敏感——**所以这个错误不会让枪变形或错位,只在枪口/弹道起点上暴露,极易漏检**。
- **枪口点验收 = 从贴图不透明像素实测,不靠目测**:沿 `muzzle[1]×2` 的行带扫最右侧 alpha>40 的像素 = 真实枪尖,与 `muzzle[0]×2` 比对,偏差应 ≤1px(现役四把枪:0 / 0.6 / 0.6 / -1.1)。游戏内再用调试十字(getMuzzle 世界坐标画十字+圆)叠在放大 4 倍的画面上人眼复核。
- **骨盆宽度 = ±2【勿改】**: 宽骨盆⇒侧视下两条大腿从相距很远的胯点画向不同角度⇒"一长一短"错觉,任何统一轨迹方案都救不了。站姿开脚感靠腿角度实现,不靠胯距。
- **翻转镜像**: 普通件 flipX 且 origin 沿 x 取 1-u;瞄准件保持真角度 + flipY 且 origin 沿 y 取 1-u。忘了 origin 镜像 → "朝左完全变了个样"(非对称贴图关节点偏移 (1-2u)·尺寸)。
- **步态 IK 必须按各自真实胯点解算**(constructor 里从 parts 读 _hipDxF/_hipDxB),从身体中心解会造成两腿提膝高度不一致。
- **头部世界空间随瞄**: clamp(pitch·0.55) 减去躯干自身俯仰,否则跪姿/跑步躯干前倾会带着头低下去。
- ikLegs 入 rigs.json(player [19.5,31]=sole 模型,robot [20.5,34.5])。
- Matter 关节锚点传"创建时刻原始世界偏移",禁止预旋转(HIGH 级历史缺陷)。
- Phaser 4:setTintFill 已移除 → setTint(c).setTintMode(Phaser.TintModes.FILL),恢复时还原 MULTIPLY。
- **"复现即复位"(R3 审查确认的缺陷模式)**:玩家死亡期间 Player.update 早退→updatePose 不跑→骨架上的瞬态状态(受击 flinch、Verlet 链位形)冻结在死亡帧,重生 setVisible(true) 时若不清零=复活第一帧重播幽灵甩头/链从尸体位甩过来。定式=setVisible(true) 里集中清一切瞬态(_flinchT=0、_pdReset=true);新加任何"随帧衰减"的骨架状态都要进这份清单。
- **受击形体冲击(hitJolt,R3 定版)**:接触点分区=当前胶囊顶 1/4 为头区(**禁止固定像素阈值**——蹲姿胶囊 52<66 曾让蹲/跪永远判不到头);躯干项必须加在头部世界稳定项取值之前(头自动抵消),头项显式叠加,否则躯干渗漏削平头/躯干区分度。头区=甩头为主(头10°/躯干3°),躯干区=晃身为主(6.5°/3.5°),×0.85-1.15 随机,exp(-dt·14) 衰减。敌人同款(非致命才 jolt),不与白闪禁令冲突。

## C. 步态与姿态系统(全部定版,核心资产)

实现=分段 IK 足迹环(CharacterRig updatePose),方法论:**"指定脚在哪、反解角度"(IK),不要 FK 手调**;凡脚要贴地的动作必须 IK。

### 站立跑(v4.1)
- **步频=人类节奏【勿改快】**: runCycleLen 208(满速360 → 3.46步/秒)。步频过快是"滑稽/机器人感"的第一来源。
- **零滑步约束(数学核心)**: 触地段脚相对髋**线性匀速**后送;占空比 **D = 2A / cycleLenNow 自动反解**(A=步幅30)。正弦轨迹"只有一瞬不滑"是曾犯过的数学错误。D<0.5 自然产生换步双脚离地的飞行相="步子大"的观感来源(不是叉大腿)。
- **两个直腿时刻(解剖学硬指标)**: ①蹬离端腿后伸近全直(不对称滚动弧 rollLand10/rollPush5+尖朝下38°,IK 距离逼近腿全长自然蹬直);②终末摆动伸膝前探(提膝曲线 sin(π·min(1,s^1.25/0.88)) 末段~12%归零)。腿只在摆动中段折叠——"全程屈腿"=怪。
- **踝关节全程转动(~54°)**: 跟落勾脚-16° → u=0.3 拍平 → 中段贴地 → u=0.5 起脚跟先离地踝下压 → 蹬离38°(入侵者2实测≈40) → 摆动前15%保持下垂拖尾 → 落地前勾起。摆动折叠段脚随小腿35%(fF=0.95−0.35·lift)。
- 提膝 H=14 峰值偏后段 + 后拖 TRAIL=7(折叠剪影);髋部起伏 cos2θ×2.2px(每步一次,飞行高/触地微压);躯干节律 sin2θ×±2.2° + 跑步前倾 4.5°(修"上半身像固定玩偶";头部世界稳定与枪口锁定天然不受影响)。
- 站姿(待机版):stance (-16, 37, 17, 10),比母本战斗姿收拢,后膝带微弯。

### 后退【定版】
- **专门动作=贴地滑步**: A=22 / backCycleLen=165(≈3.7步/秒) / H=2.5 / roll 4-3 / 尖压10° / 微后仰-2°(runLean 分支) / 髋起伏减半。**脚全程擦地,绝不提膝**(轨迹最高≈5px)。
- 限速 backSpeedFactor **0.85**;movingBack = 输入方向 ≠ 朝向(Player.js)。历经"倒放前进→高频碎步→大步慢频→贴地滑步"四轮否定,勿回退。

### 蹲行【勿改】
- 髋钉低位双骨 IK,步幅 **±24 勿改**,crouchCycleLen 136。
- **脚掌角色化**: 压平系数随相位轮换——前伸承重脚=平踩(1.0),折叠到臀下的脚=脚跟抬起脚尖点地(0.24 顺小腿)+踝抬3px。**按骨架槽位写死必穿模**(水平脚掌嵌进横置小腿)。

### 跪姿(军姿几何)
- drop=25(髋22) / tF=-113(大腿从髋**上斜**23°,前膝高于髋) / sF=109(小腿世界角-4°微前倾)→ **踝关节张开94°** / tB=25, sB=71(后膝近地、靴尖点地,后脚压平0.3)。
- 教训:紧凑不能靠压死踝关节(曾把小腿后斜40°把踝压到50°=用户点名"太紧")。

### 跳跃(四相位+蓄力)
- **先屈腿再跳**: 按跳后 jumpWindupMs=85ms 预备下蹲(复用落地压缩 IK 通道压到0.85)→到点 _doJump 且 landT 清零(squash→stretch 瞬间蹬直)。土狼跳不蓄力。
- 空中姿态由 vyNorm=vy/jumpVel 驱动:蹬伸(-1,腿伸展尖绷22°)→收腿(0,膝收向胸)→前伸探地(+1,脚放平-8°)。
- **落地压缩必须 IK**(双脚钉地、髋沉6k、前倾6°k,landT=0.45+0.55·impact,~180ms 弹性恢复)——FK 弯膝会"悬空压缩"。

### 停步
- gaitIntensity 进 dt·6(起步柔)/出 dt·14(快速落定)。出得慢=松键后腿"融化"回站姿的别扭感。

### 通用原则
- **手感/审美类改动必须用户试玩拍板**;技术上"更正确"≠"更好看"(髋部节律曾按物理做成"触地最低"结果读作半蹲跑)。
- 部件的姿态修正系数(压平/滚动)必须绑定"该腿此刻的步态角色",不能绑定骨架槽位。
- 敌人共享全套骨架逻辑:Enemy.js 设 rig.cycleLenNow(战斗前进208/后撤165/**巡逻走104**)、gaitIntensity≤0.8;无 airT 字段自动惰性。**慢速必配短周期**:D=2A/cycleLen,巡逻 60 速配 104 自动解出 D≈0.58=双支撑行走;沿用跑步周期 208 在慢速下有飞行相,读作漂浮慢动作。
- 巡逻行为(2026-07-15 定版,enemies.json 全 config):慢踱步 60+端点驻足 1.2-3s(过半转身张望)+途中随机驻足;撞障碍=端点待遇;发现目标才提速 chaseSpeed。
- 敌人受击**不做白闪**(反馈=硬直+击退+火花);白闪仅玩家掉血警示。

## D. 断肢/尸体物理(GibSystem)

- 金属零件落地配方【定版】: restitution 0.03 / friction 0.85 / frictionStatic 1.2 / frictionAir 0.02 / sleepThreshold 32;关节 stiffness 0.42 / damping 0.28。
- **落地安定=静止即烘焙(2026-07-15 三轮返工定版)**:整具全部件低速持续 40 帧→全转 isStatic;鞭尸/断肢瞬间 unfreeze→受力→自动再冻结。堆叠尸体的 resting-contact 振荡+碰撞级联唤醒靠睡眠机制永远收不干净——细节与验收方法(位移窗口法)见 level-devices-pipeline G 节。
- 飞行中关节 0.42/0.28 仍足以连体,配方不变。
- **【武器冲击力三层,2026-07-25 用户两次点名"超级大炮单发冲击力跟步枪一样小"后定版】**"冲击力"在玩家眼里=**被打的东西飞多远**,而它分散在三条互不相通的路径上,必须**逐条按武器配置**,漏一条用户就会点名:
  1. **可推物/气瓶** → `ArenaScene.onHitWall` 的 `weapon.impactForce`。**旧版是全武器共用常数 0.007**=大炮与步枪字面等力,且只推得动 4px。实测标定(38×34 弹药箱单发位移):0.007→4px / 0.02→11px(步枪轻推)/ 0.045×7弹丸→172px(霰弹轰飞)/ 0.25→137px / 0.75→410px+翻滚242°(大炮掀飞)。
  2. **击杀 → 尸体** → `GibSystem.spawnRagdoll` 的 `weapon.corpseLaunch`(px/step)。**`hitKnockback` 对秒杀型武器完全无效**——`Enemy.takeHit` 里刚给 `_knockVx` 赋完值就 `alive=false`,Enemy.update 再不跑,那 320 直接被丢弃;**大炮一发必秒杀 ⇒ 它的冲击力 100% 由尸体起飞速度表现**。实测标定(B4 甲板整具净位移):6→17px(步枪一顿)/ 20→58px / 45→130px / 75→189-215px(大炮轰飞并翻滚)。竖直系数随初速递减(0.30→0.18)且总量夹到 -0.5v,否则大威力把尸体抛出画面。
  3. **鞭尸尸块** → `GibSystem.hitGibBody` 的 `weapon.corpseImpulse`(早已按武器配)。**两道钳(2026-07-26 自审复核)**:①40ms 窗口内同尸累计冲量封顶 ×1.6、断肢只掷窗口首发——霰弹 7 弹丸曾各自结算叠到 0.084>大炮 0.055、断肢 1-0.55⁷≈0.99>0.9 双倒挂(与活敌击退叠加同模式,**多弹丸武器的"逐弹独立结算叠加超车"要当一类 bug 搜**);②轻部件 Δv 封顶 70px/step(cap=70·m/277.8)——arm/foot 质量仅 0.042-0.046,大炮力单步 Δv=F/m×16.667²=360px 读作瞬移;躯干 m=0.50 够不到帽=签收手感零变化。
  - **验收必须量真实位移,不能量账面初速**:改前大炮尸体账面速度是步枪的 3.8 倍,实际位移只多 31px(44 vs 13)——摩擦 0.85/frictionStatic 1.2 与关节阻尼把动能几乎吃光,肉眼完全读不出差别,所以"数值改了"≠"手感改了"。

## E. 验收方法论(自动化,不开人眼盯不准的东西)

- 钩子:window.__game / __tw(scene/player/killAll/teleport);开始遮罩关闭=`scene.input.emit('pointerdown')`;输入钉住=包裹 `scene.input2.update`(moveX/aimX/aimY/firing)。
- **泵帧**: `game.loop.step(t += 16.7)` 循环(窗口遮挡也照跑);**冻结拍照** `loop.sleep()` / 恢复 `wake()`。
- **定相取帧**: 直接设 `player.gaitPhase = 目标相位 − 每帧增量` 再 step 一帧。**不要循环追相位**——步进 ~0.2rad 与容差窗口近共振,300 帧都撞不进去。
- **假 FPS 警报**: 泵帧或窗口遮挡时,HUD FPS 表与 rAF 计数**全是节流假象**(曾出现"FPS 22/6"恐慌)。测真实开销=手动 step N 帧计墙钟(如 60帧/92ms=651fps 能力)。
- teleport 勿传进边界墙/道具内(碰撞解算每帧钉住+vx 恒 0,表现为"怎么都不动")。
- 姿态验收清单:同相位 F/B 两腿形状逐像素一致、脚不穿地不悬空、踝角自然、镜像朝左=朝右精确镜像、跪/蹲/跳回归。

## F. 参考游戏分析台(动作标杆)

- **《入侵者2》(Intrusion 2) = 一切动作的对标标杆**(用户认定)。本地 Ruffle 台:`node tmp-cuts/pb2/server.mjs` → 127.0.0.1:8799/pb2.html;全部 2629 张原件位图在 tmp-cuts/pb2/ffdec-test/(JPEXS 导出,按名检索)。
