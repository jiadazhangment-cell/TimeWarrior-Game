## 调研结论先行

四个关键决策,后面逐条展开依据:

1. **爆炸局部化,不做全屏场**——用一个尺寸贴合爆炸半径的小离屏 FBO 域,而非铺满 960×540 视口。
2. **fuel(燃料)+temperature(温度)双标量场是行业实证方案**,不是我的臆造——SIGGRAPH'02 Nguyen/Fedkiw/Jensen《Physically Based Modeling and Animation of Fire》首创"分别求解气化燃料场与高温产物场"的双场模型,GitHub 上 andrewkchan/fire-simulation 是这个模型在 WebGL 上的完整实时复刻,我已拉取其全部 GLSL 源码逐行核对,下面给的公式和默认值都来自这份能跑的代码,而非转述。
3. **温度耗散不能简单调一个数**——因为组合公式里有 `max(temp, fuel*burnTemp)`,温度会被燃料"续命",真正决定"存活多久"的是燃料衰减率,COOLING 只管余烬怎么熄。这是读源码才发现的关键坑,后面专门展开。
4. **黑体映射直接抄 CIE Planckian-locus 多项式近似**,已验证的可用 GLSL 全文奉上,比手搓渐变靠谱。

## 一、模拟域:局部化 vs 全屏

两个参考实现的分辨率策略:

| 项目 | SIM(速度/压力/散度/涡度) | DYE/温度/燃料(视觉场) | 场景定位 |
|---|---|---|---|
| PavelDoGreat/WebGL-Fluid-Simulation | 128 | 1024(8×) | 全屏装饰性玩具,鼠标满屏拖拽 |
| andrewkchan/fire-simulation | 256 | 512(2×) | 单个持续燃烧的篝火,画面占比中等 |

两者共同点:**视觉场(dye/温度/燃料)分辨率永远高于求解场(速度/压力)**——压力投影只需解决大尺度散度,粗网格足够;而颜色/温度边缘的视觉细腻度才需要高分辨率插值。这个分离本身就是抄作业的重点。

**对你们的爆炸场景**,建议不做全屏:

- 视口 960×540,但爆炸是局部特效,不该按整屏分辨率摊销成本。做法:每次爆炸开一个独立小离屏域,尺寸略大于预期最大视觉半径(留 1.5~2× 余量给膨胀和烟扩散),而不是绑定屏幕像素网格。
- 推荐网格:**SIM 96×96(或 128×128 若预算允许),DYE/TEMP/FUEL 192×192**(2× 比例,抄 fire-simulation 的比例而非 Pavel 的 8×——8× 是给"展示型全屏玩具"用的奢侈比例,爆炸不需要)。
- 并发多个爆炸(手雷+枪口焰同时存在):池化 4~8 组独立 FBO 集合复用,不要让多个爆炸共享同一张大图——成本应该跟着"有效爆炸面积"走,不是跟着屏幕面积走。
- 每个爆炸实例每帧开销 ≈ 十几个 pass(见下方管线)× PRESSURE_ITERATIONS,网格小(96²/128²)所以即使迭代数给到 30~40 也远比全屏合算。

## 二、通道设计(抄 andrewkchan/fire-simulation 的场布局)

| 场 | 类型/格式 | 含义 |
|---|---|---|
| `velocity` | vec2, RG16F, ping-pong | 速度场 |
| `pressure` / `divergence` / `curl` | float, R16F | 求解器中间量,無需 ping-pong 的可用单缓冲(divergence/curl),pressure 需要 ping-pong |
| `fuel` | float 0~1, R16F, ping-pong | 未燃燃料浓度("reactant") |
| `temperature` | float, R16F, ping-pong | 温度,决定颜色与浮力 |
| `density`(烟) | RGB 或 R16F, ping-pong | 惰性烟/燃尽产物示踪场,纯被动染料,不参与燃烧 |

这精确对应 Nguyen/Fedkiw/Jensen 论文里"分别对气化燃料与高温气体产物建模"的思路,只是把论文的 level-set/PDE 求解换成了实时 Jacobi 迭代版本。

## 三、每帧管线顺序(逐行核对自 andrewkchan/fire-simulation 的 `step(dt)`)

```
1.  注入 fuel(爆炸=一次性 splat;篝火=每帧持续喷射粒子/splat)
2.  combustion:   燃烧 fuel→temperature,施加冷却
3.  advect velocity(应用 velocity 耗散)
4.  curl(+ 把噪声混入 curl,廉价伪造次网格湍流)
5.  vorticity confinement(施加涡度约束力)
6.  buoyancy(温度 → 向上的力)
7.  pressure 热启动衰减(Jacobi 迭代前,把上一帧 pressure 乘一个 <1 系数作初值)
8.  divergence
9.  Jacobi 压力迭代 × N
10. 梯度减法(projection,把无散场投影出来)
11. advect density/烟(应用 density 耗散)
12. advect temperature(耗散=1.0,即【不】额外衰减——见下方重点)
13. advect fuel(应用 fuel 耗散)
14. advect 噪声场(耗散=1.0)+ 混入新鲜噪声刷新噪声场
```

**注意第 12 步**:温度平流时 dissipation 硬编码成 `1.0`,即温度不会因为平流额外衰减——冷却完全交给第 2 步的 Stefan-Boltzmann 式物理冷却项负责。这是有意的职责分离,不是疏漏。

**⚠️ 重要陷阱——两种耗散约定不能混用:**

- Pavel 的写法(**推荐,帧率无关**):
  ```glsl
  float decay = 1.0 + dissipation * dt;
  gl_FragColor = result / decay;
  ```
- fire-simulation 的写法(**帧率相关,有 bug 风险**):
  ```glsl
  gl_FragColor = dissipation * texture2D(uSource, coord); // 隐含假设固定 60fps!
  ```
  上表 FUEL_DISSIPATION=0.92、DENSITY_DISSIPATION=0.99、VELOCITY_DISSIPATION=0.98 都是**按每帧固定倍率**乘的,没有 dt 归一化——在 60fps 下调好看,换一个帧率画面观感就变了。你们的项目照抄这套数字前,必须转换成连续速率形式:

  ```glsl
  // 把 "每帧倍率 k60"(60fps 下测得好看的数)转换成连续衰减率(单位 1/秒):
  // continuousRate = -ln(k60) * 60
  // 之后每帧用:
  value *= exp(-continuousRate * dt);   // 或等价的 value /= (1.0 + continuousRate * dt);
  ```
  例如 FUEL_DISSIPATION=0.92 → continuousRate ≈ -ln(0.92)*60 ≈ **5.0/秒**,之后用 `fuel *= exp(-5.0*dt)` 才是帧率无关的正确写法。

### 4.2 GPU Gems 第 38 章(Mark Harris,Fast Fluid Dynamics Simulation on the GPU)给出的通用准则

- 算子分解:`S = P∘F∘D∘A`(投影∘加力∘扩散∘平流)
- 半拉格朗日平流:`q(x, t+Δt) = q(x − Δt·u(x,t), t)`,双线性插值,时间步/流速无条件稳定
- Jacobi 迭代压力泊松方程模板:`x_new = (α·x_L + α·x_R + α·x_B + α·x_T + β·b_C) / β`(压力:`α=-(Δx)²`, `β=4`)
- **迭代数下限**:原文明确"少于 20 次迭代会有明显误差";高质量场景"通常用 40~80 次"。这解释了为什么 Pavel 和 fire-simulation 都不约而同选了 **20 作为实时下限**。
- **浮力完整公式**(比 fire-simulation 的简化版更完整):
  ```
  F_buoy = ( −s·(T − T₀) − k·d ) · ĵ
  ```
  其中 `s`=浮力系数,`T₀`=环境温度(不是 0),`k`=烟密度权重,`d`=烟/密度场,`ĵ`=向上单位向量。fire-simulation 的实现只保留了 `−s·T` 这一项(把 T₀ 当 0、烟不计重量),你们的爆炸如果想要"重烟下沉、热气上升"的层次感,建议把完整版抄回来。

## 五、存活 0.5~1.5s 怎么配——先看清楚耦合关系

combustion shader 原文(逐字核对无误):

```glsl
float fuelTemperature(float fuel) { return fuel * burnTemperature; }

void main () {
  float temp = texture2D(uTemperature, vUv).x;
  float fuel = texture2D(uFuel, vUv).x;
  // 冷却:Stefan-Boltzmann 式,T^4 次方衰减
  temp = max(0.0, temp - dt * cooling * pow(temp / burnTemperature, 4.0));
  // 续命:只要还有燃料,温度立刻被顶回 fuel*burnTemperature
  temp = max(temp, fuelTemperature(fuel));
  gl_FragColor = vec4(temp, 0.0, 0.0, 1.0);
}
```

**关键洞察(读代码才发现,不是显然的)**:`max(cooled_temp, fuel*burnTemp)` 意味着只要 fuel 没耗尽,温度每帧都被"续命"顶回燃料对应的温度——**COOLING 在燃料没烧完之前基本不起作用**。也就是说:

- **火焰"存活多久"的主控参数是 FUEL 的衰减速度**,不是 COOLING。
- **COOLING 只决定燃料烧完之后,最后那点余烬多快熄灭变黑**(尾巴的"脆度"),对总时长影响很小。

**配方(fuel 是干净的单指数衰减,可以精确解):**

```glsl
// fuel(t) = fuel0 * exp(-k * t)
// 目标:t = duration 时 fuel 已降到"视觉上完全不可见"的阈值 ε(建议 ε≈0.01)
// k = ln(1/ε) / duration ≈ 4.6 / duration   (ε=0.01 时)
fuel *= exp(-k_fuel * dt);
```

| 目标存活时长 | k_fuel(1/秒) |
|---|---|
| 0.5s(短促干脆) | ≈ 9.2 |
| 1.0s | ≈ 4.6 |
| 1.5s(略拖尾) | ≈ 3.1 |

COOLING 的作用只是调"余烬熄灭的脆感":数值越大,燃料耗尽后残余温度归零越快(干脆收尾);越小则拖出一段暗红余烬(拖泥带水但更真实)。因为耦合了 `pow(temp/burnTemp,4)`,这条衰减曲线本身就是先快后慢的非线性形状(不是线性也不是简单指数)——这正好天然满足你要的"无帧感"观感,不需要额外手工缓动。**不要指望用 COOLING 去控制总时长,先用 k_fuel 打满 0.5~1.5s 目标,COOLING 留着专门调尾巴脆不脆。**

**额外建议**:fire-simulation 源码里其实预留了"把噪声直接混进 fuel 场"的代码,但被注释掉了:
```glsl
// fuel += noise * noiseBlending;   ← 被注释掉,未启用
```
这行如果启用(或做等价实现),会让 fuel 场边界本身带噪声扰动——**这是直接命中你"火焰底边自然不规则"需求的现成开关**,建议在你们的实现里打开它(或在爆炸刚炸开的第一帧就把这类噪声叠加到 fuel splat 上,而不是等它随流场演化几帧后才变得不规则)。

## 六、注入(爆炸初始冲量)

**燃料注入**——两个参考实现都不是"加一个任意量",而是**用 max-blend 直接饱和到 1.0**:

```glsl
// splat 的通用高斯核(两个项目公用同一形式):
vec2 p = vUv - point;
p.x *= aspectRatio;                          // 非方形域时保持爆炸是圆形而非椭圆
float splat = exp(-dot(p, p) / radius);      // 注意:除的是 radius,不是 radius²
                                              // 等效 sigma_uv ≈ sqrt(radius/2),
                                              // 可见范围(~3σ)≈ 3*sqrt(radius/2)
fuel = max(fuel, splat);                     // useMax=true:饱和式注入,不会叠加爆表
```
**温度不需要单独注入**——fire-simulation 完全没有对 temperature 做 splat,温度 100% 由 combustion 步骤从 fuel 派生(`temp = fuel*burnTemperature`)。fuel 注满 1.0 后,下一次 combustion pass 自动把温度顶到 burnTemperature。这比自己再调一个温度注入量省心。

**爆炸专属扩展 1——"闪光"温度尖峰**(参考实现没有,针对爆炸新增,原理稳妥):
```glsl
// 在爆炸核心区(半径小于 fuel 半径)额外叠加一个比稳态燃烧温度更高的瞬时尖峰,
// 制造爆炸特有的"第一帧极亮白光,随后迅速降到正常火焰色"效果。
// 因为冷却项是 T^4,越高温冷却越快,这个尖峰会自己在几帧内烧回正常火焰温度上限,不需要额外手动淡出。
float flash = exp(-dot(p, p) / flashRadius);  // flashRadius < fuelRadius,只覆盖最核心区域
temperature = max(temperature, flash * flashPeakTemp);  // flashPeakTemp ≈ 1.5~2.0 × burnTemperature
```

**爆炸专属扩展 2——径向速度冲量**(两个参考项目的 splat 都是"鼠标拖拽方向"的定向冲量,没有径向爆炸案例,以下是标准手法的合理外推):
```glsl
vec2 p = vUv - center;
p.x *= aspectRatio;
float falloff = exp(-dot(p, p) / (radius * radius));   // 这里按标准高斯写法平方了 radius,和上面 fuel 的写法区分开
vec2 dir = (dot(p,p) > 1e-8) ? normalize(p) : vec2(0.0);
velocity += dir * impulseStrength * falloff;
```
`impulseStrength` 的量级没有普适数字可抄(两个参考项目的速度场单位约定不同,Pavel 用 SPLAT_FORCE=6000 配合大幅衰减,fire-sim 直接传原始 dx/dy 没有额外力度系数)——**建议按你们引擎的实际像素/秒来定义速度场单位**(不要沿用参考项目的抽象 uv/s),用一个视觉目标去反推:"冲量应该让火球在存活期内视觉半径膨胀到初始的 1.5~2.5 倍",再试调 impulseStrength。

**建议**:别指望一次性单帧注入的完美高斯核会自然不规则——它注入瞬间就是个数学意义上的正圆。要"从第一帧就不规则",在爆炸触发的同一帧里,同时对 fuel/velocity 叠加一次性的强噪声扰动(复用上面第五节提到的噪声混合机制,一次性给个较高 blend 而非每帧的常规小扰动),而不是指望涡度约束用几帧时间把圆形搅乱。

**浮力的创作方向提醒**:篝火需要持续上升成一根烟柱,BUOYANCY=0.2 是为这个目标调的。**爆炸不是这样**——爆炸读起来应该是"径向炸开 + 原地滚烫翻腾 + 烟缓慢上飘",如果直接照抄篝火的浮力强度,火球会不自然地迅速变成一根上升的火柱,而不是原地滚爆炸开的团块。建议爆炸的 BUOYANCY 明显调低于 0.2(起步 0.05~0.15),让径向冲量主导初期形状,浮力只负责让烟雾残留物慢慢飘走。

## 七、障碍物边界(场景固体遮挡)——三方独立来源互相印证

核对到的规律,速度与压力的边界条件**处理方式不同**,且两个参考项目在**各自域边缘**都是这么做的(压力用夹取,速度用取反),GPU Gems 原文的表述完全吻合:

- **速度/散度场:no-slip 实心墙**——取相邻格子的值,**取反**后当作"墙内"的采样结果:
  ```glsl
  // fire-simulation 的 divergenceShader 写法(域边缘版,取反+夹取二合一):
  vec2 sampleVelocity(vec2 uv) {
    vec2 multiplier = vec2(1.0);
    if (uv.x < 0.0) { uv.x = 0.0; multiplier.x = -1.0; }
    if (uv.x > 1.0) { uv.x = 1.0; multiplier.x = -1.0; }
    if (uv.y < 0.0) { uv.y = 0.0; multiplier.y = -1.0; }
    if (uv.y > 1.0) { uv.y = 1.0; multiplier.y = -1.0; }
    return multiplier * texture2D(uVelocity, uv).xy;
  }
  ```
- **压力场:纯 Neumann 开放边界**——直接夹取位置,**不取反**,与相邻格子同值(零梯度):
  ```glsl
  vec2 boundary(vec2 uv) { return clamp(uv, 0.0, 1.0); }
  ```

这套逻辑目前两个参考项目都只用来处理"离屏纹理的四条外边缘",**没有处理内部任意形状的固体障碍物**——这部分需要你们自己泛化,但泛化方式是标准做法(Stam《Real-Time Fluid Dynamics for Games》GDC 2003 的 `set_bnd` 就是同一套逻辑按格子逐个推广),风险很低:

```glsl
// 额外准备一张 solidMask 纹理(0=流体格,1=固体格),分辨率跟 SIM 一致。
// 速度/散度阶段,把"越界"判断换成"邻居是否是固体格":
vec2 sampleVelocityWithObstacles(vec2 uv, vec2 selfUv) {
  float solid = texture2D(uSolidMask, uv).r;
  if (solid > 0.5) {
    // 邻居是固体:取自己的值再取反,模拟"贴着墙、法向速度为零"
    return -texture2D(uVelocity, selfUv).xy;
  }
  return texture2D(uVelocity, uv).xy;
}

// 压力阶段同理,但不取反(等于自身值,零梯度,流体"推不动"墙但也不会被墙吸走压力):
float samplePressureWithObstacles(vec2 uv, vec2 selfUv) {
  float solid = texture2D(uSolidMask, uv).r;
  return solid > 0.5 ? texture2D(uPressure, selfUv).x : texture2D(uPressure, uv).x;
}

// fuel/temperature/density 三个可视场:简单粗暴地在固体格强制清零,防止火焰视觉穿模:
temp = mix(temp, 0.0, solidMaskAtSelf);
fuel = mix(fuel, 0.0, solidMaskAtSelf);
```
`solidMask` 的生成:把关卡里的 solids/障碍物几何,在爆炸触发时一次性栅格化到爆炸局部域对应的分辨率上(离屏渲染一个黑白 mask,或 CPU 端算出覆盖的格子范围直接写 texture)——这部分要接关卡的碰撞几何,超出本次调研范围,只把公式给你们对接。

## 八、黑体色谱映射(温度→颜色)——两套方案

### 方案 A(推荐,直接抄,已含亮度物理曲线):CIE Planckian-locus 多项式近似

逐字核对自 andrewkchan/fire-simulation 的 `displayFireShader.glsl`,能直接跑:

```glsl
vec3 blackbody(float t) {
  // 把内部温度单位重新归一化到一个固定的等效 Kelvin 范围(这里钉死在约 3000K 顶峰,
  // 也就是普通木柴/汽油火焰的典型色温——不是刻意调蓝调白的那种高温电弧)
  t *= (3000.0 / burnTemperature);

  // Planckian locus 在 CIE 色度空间的多项式近似
  float cx = (0.860117757 + 1.54118254e-4*t + 1.28641212e-7*t*t)
           / (1.0 + 8.42420235e-4*t + 7.08145163e-7*t*t);
  float cy = (0.317398726 + 4.22806245e-5*t + 4.20481691e-8*t*t)
           / (1.0 - 2.89741816e-5*t + 1.61456053e-7*t*t);

  // 色度坐标 → XYZ 三刺激值
  float d = (2.0*cx - 8.0*cy + 4.0);
  vec3 XYZ = vec3(3.0*cx/d, 2.0*cy/d, 1.0 - (3.0*cx + 2.0*cy)/d);

  // XYZ → 线性 RGB
  vec3 RGB = mat3(
     3.240479, -0.969256,  0.055648,
    -1.537150,  1.875992, -0.204043,
    -0.498535,  0.041556,  1.057311
  ) * vec3(XYZ.x / XYZ.y, 1.0, XYZ.z / XYZ.y);

  // 关键一步:Stefan–Boltzmann 亮度标定——低温=暗(几乎不可见),高温=亮到过曝
  return max(RGB, 0.0) * pow(t * 0.0004, 4.0);
}
```
这一套自带"低温暗红→高温刺眼近白"的亮度曲线(靠最后的 `pow(...,4.0)`),不需要另外叠加一条手工亮度渐变——**这是它比方案 B 更适合直接拿来渲染火焰的原因**。

配套的"只在还有燃料的地方画火焰"技巧(把颜色和 fuel 存在与否解耦,是让火焰边缘服帖、不"温度飘出去了颜色还留着"的关键):
```glsl
float visibility = tanh(10.0 * fuel);   // fuel≈0→不可见,fuel>0.2 后迅速趋近 1
finalColor = visibility * blackbody(temperature);
```

### 方案 B(备选,更便宜,但没有内置亮度曲线):Tanner Helland 回归公式

来自摄影白平衡领域的经典拟合(基于 Mitchell Charity 的黑体辐射实测数据,1000K~40000K 有效,R²>0.987),**只给色度、不给亮度**——低温和高温在这套公式里都是"满亮度"的,必须自己另外叠一条亮度曲线(比如低温处乘一个趋近 0 的系数)才能用在火焰上:

```glsl
vec3 kelvinToRGB(float kelvin) {
  float k = kelvin / 100.0;
  float r, g, b;

  r = (k <= 66.0) ? 255.0 : 329.698727446 * pow(k - 60.0, -0.1332047592);

  g = (k <= 66.0)
    ? 99.4708025861 * log(k) - 161.1195681661
    : 288.1221695283 * pow(k - 60.0, -0.0755148492);

  b = (k >= 66.0) ? 255.0
    : (k <= 19.0) ? 0.0
    : 138.5177312231 * log(k - 10.0) - 305.0447927307;

  return clamp(vec3(r, g, b) / 255.0, 0.0, 1.0);
}
// 用法示例(手工叠亮度曲线):
// vec3 color = kelvinToRGB(mix(1000.0, 6000.0, temp01)) * pow(temp01, 2.0);
```
**结论:优先用方案 A**,除非你们发现 `mat3` 乘法在批量 draw call 下有性能压力,再退化到方案 B + 手工亮度曲线。

## 九、烟(燃尽产物)渲染

烟就是 fire-simulation 里的 `density` 场——**一个普通的被动染料场**,跟 dye 没区别,不走黑体计算:
- 注入:爆炸时用普通加法 splat(`useMax=false`),颜色给深灰/焦褐色(比如 `vec3(0.08,0.07,0.06)`)。
- 衰减:比火焰本身更慢,建议 DENSITY_DISSIPATION 对应的连续衰减率取火焰 k_fuel 的 1/3~1/2(让烟在火光熄灭后继续飘一段,视觉上更自然的余韵)。
- 渲染:直接输出 RGB,**不经过 blackbody()**。

## 十、与黑底 ADD 叠加的注意点

1. **火焰层用纯加法混合**(`gl.blendFunc(gl.ONE, gl.ONE)`),离屏 FBO 清屏色定为纯黑 `(0,0,0)`。黑色像素加到任何背景上贡献为零,天然没有矩形/圆形的"贴图边框感"——这正是你想要的"无边界感"效果的关键,不需要额外做羽化遮罩来藏边缘。
2. **烟不能用加法混合**——加法只能让画面变亮,烟应该让背景变暗/变灰,必须走普通透明度混合(`gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA`),且这一层要用独立的 draw call/独立 blend state,不能跟火焰共用一次绘制。建议顺序:先画烟(半透明混合,压暗背景),再画火焰(加法叠加,提亮),两者视觉上自然咬合(烟里透着火光)。
3. **HDR 溢出/tonemap**:blackbody() 最后的 `pow(t*0.0004,4.0)` 在高温区数值会远超 1.0。如果直接写入一个 8-bit 输出目标,核心会被硬裁成一坨死白,丢失渐变细节。两个可选处理:
   - 简单裁剪 + 提前把 burnTemperature/亮度系数调到"裁剪发生的位置刚好在核心几个像素内"(两个参考项目实际上就是这么处理的,没有做额外 tonemap);
   - 或者在最终合成前过一道简单 Reinhard(`color/(1.0+color)`)再叠加,细节保留更好,但会削弱"爆炸瞬间刺眼过曝"的冲击力——爆炸场景其实更适合**不做 tonemap、放任核心过曝**,过曝本身就是爆炸的视觉语言。
4. 中间计算(温度、blackbody 输出)全程建议用浮点 FBO(RGBA16F/R16F,两个参考项目都是 `HALF_FLOAT`),只有最终合成到游戏画面那一步落到 8-bit 背板。

## 十一、汇总:一次爆炸的最小可用管线(伪码级,可直接顺着抄)

```glsl
// ===== 每次爆炸触发时(仅一帧)=====
fuel        = max(fuel,        gaussianSplat(center, fuelRadius));            // 饱和到 1.0
temperature = max(temperature, gaussianSplat(center, flashRadius)*flashPeak); // 可选闪光尖峰
velocity   += radialSplat(center, blastRadius, impulseStrength);              // 径向冲量
density    += gaussianSplat(center, smokeRadius) * smokeColor;                // 烟,加法注入
noiseField  = mix(noiseField, strongBurst, oneShotBlend);                     // 一次性强噪声,破坏正圆

// ===== 每帧 =====
temp   = max(0.0, temp - dt*COOLING*pow(temp/BURN_TEMP, 4.0));  // 冷却(T^4)
temp   = max(temp, fuel * BURN_TEMP);                            // 燃烧续温
velocity = advect(velocity, velocity, dt) * exp(-VEL_K*dt);
curl     = computeCurl(velocity) + NOISE_BLEND * bigNoise();
velocity = applyVorticityConfinement(velocity, curl, CONFINEMENT, dt);
velocity += dt * BUOYANCY * temp * vec2(0,1);                    // 浮力(爆炸调低此系数)
pressure *= PRESSURE_WARMSTART;                                  // 0.8
divergence = computeDivergence(velocity);   // 边界:solidMask→取反
for (i in 0..PRESSURE_ITERATIONS) pressure = jacobiStep(pressure, divergence); // solidMask→夹取不取反
velocity = subtractPressureGradient(velocity, pressure);
density = advect(density, velocity, dt) * exp(-SMOKE_K*dt);
temp    = advect(temp, velocity, dt);          // 不额外耗散
fuel    = advect(fuel, velocity, dt) * exp(-FUEL_K*dt);
noiseField = advect(noiseField, velocity, dt); // 不额外耗散
noiseField = mix(noiseField, freshNoise(time), NOISE_VOLATILITY);

// 固体格清零(每帧,或与上面对应阶段合并):
temp *= (1.0 - solidMask);  fuel *= (1.0 - solidMask);  density *= (1.0 - solidMask);

// ===== 渲染 =====
finalColor = tanh(10.0*fuel) * blackbody(temp);   // 火焰,加法混合,黑底 FBO
smokeColor = density.rgb;                          // 烟,普通透明度混合,单独 draw call
```
