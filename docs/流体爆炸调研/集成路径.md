## 〇、两个决定全局的前置事实(先看这两条,后面的排序全由它们导出)

### 事实 A:Phaser 4.2.1 默认只开 **WebGL 1**,但**官方支持你把 WebGL 2 上下文塞进去**

- `C:/Users/surpr/Desktop/TimeWarrior-Game/node_modules/phaser/src/renderer/webgl/WebGLRenderer.js:709`
  ```js
  gl = canvas.getContext('webgl', config.contextCreation) || canvas.getContext('experimental-webgl', config.contextCreation);
  ```
  → 自己创建时永远是 WebGL1。
- 但 `WebGLRenderer.js:703-706` 有逃生口:
  ```js
  if (game.config.context) { gl = game.config.context; }
  ```
  `config.context` 定义在 `core/Config.js:148`(`GetValue(config, 'context', null)`)。
- 而且这不是"碰运气能跑",是**明写的支持**。`WebGLRenderer.js:896-898`:
  ```js
  // Make WebGL2 core features which were extensions available on the WebGL1 context.
  // This allows us to use a WebGL2 context.
  if (gl instanceof WebGLRenderingContext)
  ```
  整段 ANGLE_instanced_arrays / OES_vertex_array_object / OES_standard_derivatives 的 shim 都包在这个 `instanceof WebGLRenderingContext` 分支里(897-934);传 WebGL2 上下文时整段跳过,因为 WebGL2 原生就有。Phaser 自己的着色器是 GLSL ES 1.00,WebGL2 完全兼容。
- 配套要求:必须同时传 `config.canvas`(`core/Config.js:143`,消费点 `core/CreateRenderer.js:73-79`),并且 **`type` 必须显式写 `Phaser.WEBGL`,不能用 `Phaser.AUTO`**——`core/CreateRenderer.js:34` 会 `throw new Error('Must set explicit renderType in custom environment')`。项目现在 `src/main.js:9` 是 `type: Phaser.AUTO`,需要改。

**意义**:WebGL2 → `EXT_color_buffer_float` 给你可渲染的 RGBA16F,且 16F 线性过滤是 WebGL2 核心特性。这是 stable fluids 速度场/压力场能不能算稳的分水岭。

### 事实 B:Phaser 的纹理包装器**造不出浮点纹理**

`renderer/webgl/wrappers/WebGLTextureWrapper.js` 的 `_processTexture` 把类型写死了:
- `:416` `gl.texImage2D(gl.TEXTURE_2D, mipLevel, format, width, height, 0, format, gl.UNSIGNED_BYTE, null);`
- `:432`、`:444` 同样是 `gl.UNSIGNED_BYTE`。

DrawingContext 建纹理时也写死 `gl.RGBA`(`renderer/webgl/DrawingContext.js:299-309`)。所以 **Phaser 自带的一切离屏目标(DrawingContext / DynamicTexture / RenderTexture / Filter 的 pool)都是 RGBA8**。

好消息:`_processTexture` 是普通原型方法(`WebGLTextureWrapper.js:390`),而 `createResource()` 在末尾调它(`:275`),**上下文丢失恢复走的也是 `createResource()`**(`WebGLRenderer.js:1052` `ArrayEach(this.glTextureWrappers, wrapperCreateResource)`)。所以**在实例上覆盖 `_processTexture` 即可得到"半浮点 + 上下文丢失自动重建"的纹理**,这是唯一一处需要碰裸 GL 的地方。

## 一、Phaser 渲染器的 GL 状态缓存 = 污染面(做任何外部 GL 前必须背下来)

Phaser 4 把整个 GL 全局状态做成缓存对象,写在 `renderer/webgl/parameters/WebGLGlobalParametersFactory.js:42-67`,**被缓存的全集**:

```
bindings: { activeTexture, arrayBuffer, elementArrayBuffer, framebuffer, program, renderbuffer }
blend:    { color, enable, equation, func }
colorClearValue, colorWritemask, cullFace(仅开关), depthTest(仅开关)
scissor:  { enable, box }
stencil:  { enabled, func, op, clear, writeMask }
texturing:{ flipY, premultiplyAlpha }     // 即 UNPACK_FLIP_Y_WEBGL / UNPACK_PREMULTIPLY_ALPHA_WEBGL
vao, viewport
```

**外加一层独立缓存**:纹理单元表 `renderer.glTextureUnits.units[]`(`wrappers/WebGLTextureUnitsWrapper.js:112-134`)。

每一项都是"先比对、相同就跳过 GL 调用"的模式,例如 `wrappers/WebGLGlobalWrapper.js:270-286`:
```js
updateBindingsFramebuffer: function (state, force) {
    var different = framebuffer !== this.state.bindings.framebuffer;
    if (different) { this.state.bindings.framebuffer = framebuffer; }
    if (different || force) { gl.bindFramebuffer(gl.FRAMEBUFFER, framebuffer ? framebuffer.webGLFramebuffer : null); }
}
```
**已知打脏点**:你直接 `gl.bindFramebuffer` / `gl.useProgram` / `gl.bindTexture` / `gl.viewport` / `gl.bindVertexArray` / `gl.blendFunc` / `gl.pixelStorei(UNPACK_FLIP_Y_WEBGL)` 之后,Phaser 的缓存与真实 GL 状态不一致 → 下一次 `drawingContext.beginDraw()`(`DrawingContext.js:708-716`,注意它是**非 force** 的 `glWrapper.update(this.state)`)会认为"已经是对的"从而**跳过重绑**,画面静默画错目标/用错程序/采错纹理。这是 Phaser 4 外部 GL 的头号事故形态。

**完全不被追踪的状态**(你动了就得自己还原):`depthMask` / `depthFunc` / `depthRange`、`cullFace(mode)`(只追踪开关不追踪面)、`frontFace`、`lineWidth`、`polygonOffset`、`pixelStorei(UNPACK_ALIGNMENT)`、`dither`。

**官方复位手段(两个 RenderNode,专为外部渲染而生)**:
- `renderer/webgl/renderNodes/YieldContext.js:57-71` —— 交出上下文:`manager.startStandAloneRender()`(冲批次)+ blend 复位 NORMAL + VAO 置 null + `glTextureUnits.unbindAllUnits()`。
- `renderer/webgl/renderNodes/RebindContext.js:67-88` —— 收回上下文:`glWrapper.update(Merge(nulled bindings, glWrapper.state), true)` **force 全量重发**(`Merge` 语义见 `utils/object/Merge.js:25-37`,obj1 优先,所以 bindings 整块被置 null 后强制重绑)+ `unbindAllUnits()`。
  ⚠️ **坑**:`RebindContext.run` 开头先执行 `renderer.clearFramebuffer(undefined, undefined, 0)`(`:75-79`)→ 对**当时绑定的那个 FBO** 发 `gl.clear(DEPTH_BUFFER_BIT)`。所以你的 render 函数返回前应该把 drawingContext 的 FBO 绑回去(Phaser 自己在 `gameobjects/extern/Extern.js:46-52` 的示例里就是这么教的)。

自救公式(不用 Extern 时):
```js
renderer.glWrapper.update(undefined, true);   // undefined + force → 从缓存全量重发,见 WebGLGlobalWrapper.js:68-77
renderer.glTextureUnits.unbindAllUnits();
```

**关键改良 ①′**:**不要用裸 `gl.*` 跑模拟 pass**。除了"半浮点纹理存储"这一件事,其余全部走 Phaser 的 wrapper API(`createProgram` / `WebGLVAOWrapper` / `createFramebuffer` / `glTextureUnits.bind` / `renderer.drawElements`)。这样:
- 状态污染风险 **≈ 0**(所有绑定都过 `glWrapper` / `glTextureUnits`,缓存永远真实);
- 上下文丢失自动恢复(所有 wrapper 都在 `glTextureWrappers`/`glFramebufferWrappers`/`glProgramWrappers`/`glVAOWrappers` 里,`WebGLRenderer.js:1048-1056` 逐个 `createResource()`);
- resize / 上下文重建不用你操心。

**状态污染风险**:①′ 下仅剩一处——覆盖 `_processTexture` 时自己发的 `texImage2D`/`texParameteri`。用 `renderer.glTextureUnits.bind(this, 0)` 先绑(`WebGLTextureUnitsWrapper.js:112`)就干净;绑完不用还原(Phaser 的单元缓存已记录)。若坚持用原始 `gl.*` 跑 pass,则必须每帧收尾做一次 `glWrapper.update(undefined, true) + unbindAllUnits()`,代价是**强制重发全部 GL 状态**(约 25-30 个 GL 调用/帧),可接受但不必要。

**每帧成本**(游戏 960×540,`config/game.json`;建议 sim 网格 256×144)
- pass 结构:advect velocity → advect(温度/燃料/烟三通道打包一张 RGBA)→ buoyancy+vorticity confinement → divergence → **Jacobi × N** → subtract gradient → obstacle enforce ≈ **7 + N** 个 pass。
- 取 N=20 → 27 draw。片元:27 × 36,864 ≈ **99.5 万** ≈ 1.9 个全屏(960×540)pass 的量。再加 1 个全屏上采样着色 pass。总计 ≈ **3 个全屏 pass 等价**,60fps 下即使核显也在 0.3-0.6 ms 量级。
- **真正的瓶颈是 CPU 侧 draw call**:27 draw × 每 draw 8-15 个 GL 调用 ≈ **250-400 次 GL 调用/帧**,Chrome 每次约 1-3 µs → **0.3-1.2 ms CPU**。→ 工程约束:Jacobi 迭代压到 ≤20,或用 red-black / 粗网格多重网格降到 8-12 次。
- 显存:RGBA16F 256×144 = 295 KB/张;速度 ×2 + 染料 ×2 + 压力 ×2 + 散度 ×1 + 障碍 ×1 ≈ **2.4 MB**,可忽略。
- 包体:着色器是字符串,几 KB。4399 静态包无压力。

**工程量**:3-5 天(含障碍 mask 生成、世界坐标锚定、火焰着色/tonemap、参数进 `config/*.json`、上下文丢失与 resize 验收)。

### 路径 ②:Phaser 4 RenderNodes / 自定义 Filter 做带状态的多 pass —— ❌ 不适合做模拟,✅ 适合做收尾合成

**API 存在性证据**
- 自定义节点注册确实公开:`renderer/webgl/renderNodes/RenderNodeManager.js:300-312` `addNode(name, node)`、`:326-340` `addNodeConstructor(name, ctor)`、`:353-370` `getNode(name)`;skill 也记载(`.claude/skills/v4-new-features/SKILL.md:139-146`)。
- **多 pass 有官方先例**:`renderNodes/filters/FilterBlur.js:101-131` —— `for (i < steps)` 循环里交替跑横/竖 pass,把上一个 DrawingContext 串给下一个。
- 自定义 filter 的骨架:`renderNodes/filters/BaseFilterShader.js:47-149`(建 ProgramManager + VBL + 全屏 quad),配一个 `filters/Controller.js:32` 的子类(构造参数第二个就是 `renderNode` 名字字符串),挂到 `gameobjects/components/FilterList.js:161` 的 `add()`。

**为什么不能做模拟**——三条硬伤,全部有源码依据:
1. **中间目标来自共享池,用完就还,内容不保留**:`BaseFilterShader.js:178-184` 从 `renderer.drawingContextPool.get(w,h)` 取,`:293` `inputDrawingContext.release()` 还回去。池的复用策略(`DrawingContextPool.js:147-228`)会按尺寸/年龄把同一个 context 发给别人,甚至 `resize()`(销毁内容)。**stable fluids 要求速度场/压力场跨帧保留**,和这个设计正面冲突。虽然有 `DrawingContext.lock(key)`(`DrawingContext.js:655-662`)能钉住,但那已经是在对抗框架。
2. **RGBA8 精度**:`DrawingContext.js:299-309` 硬编码 `gl.RGBA`,叠加事实 B → 8 bit/通道。20+ 次 Jacobi 迭代下速度场量化误差会累积成可见的块状伪影。
3. **执行时机不归你管**:Filter 在相机/GameObject 的合成链里跑,你无法控制它相对游戏逻辑(爆炸注入、障碍更新)的顺序。

**该用它的地方**:模拟结果 → 屏幕的**最后一跳**。写一个自定义 Filter(温度→火焰配色 LUT + 轻微 bloom + 热扰动),挂在火焰那一层的 `filters.internal` 上,这是 Filter 系统的正经用法,而且免费拿到 padding/裁剪管理。

**成本**:1 个全屏 pass(518K 片元)+ Phaser 自身的 filter 合成开销。**工程量**:0.5-1 天(在 ① 之上)。

### 路径 ③:DynamicTexture / Shader GameObject + `setRenderToTexture` 逐 pass 绘制 —— ✅ 强烈推荐作为**第一阶段原型**

这条路被低估了,它其实已经是一个"零裸 GL 的 ping-pong 框架"。

**API 存在性证据**
- `gameobjects/shader/Shader.js:395-428` `setRenderToTexture(key)`:
  ```js
  this.drawingContext = new DrawingContext(renderer, { width, height, camera });  // :409 —— 持久,不来自池
  this.glTexture = this.drawingContext.texture;                                   // :415
  ```

- `Shader.js:439-444` `renderImmediate()` —— 脱离显示列表,手动触发一次渲染。**这就是你的 pass 驱动器**,想跑几次跑几次。
- 输入纹理:`Shader.js:326` `setTextures([...])`,绑到 unit 0..N-1(`renderNodes/ShaderQuad.js:357-370`);uniform:`Shader.js:472` `setupUniforms(setUniform, drawingContext)` 每次渲染前回调。

  ```js

  ```
- 精度只有 RGBA8(见事实 B)。速度场需要自己做 `[-1,1] → [0,1]` 编码,压力场迭代次数别超过 ~15,否则条带明显。

- 采样与写入不能同一张纹理 → 必须两个 Shader 对象互为 A/B,或每帧交换 `setTextures` 与 `drawingContext` 引用。

**状态污染风险**:**零**。全程走 Phaser 自己的渲染节点。

**每帧成本**:与 ① 同数量级(pass 数相同),CPU 侧每 pass 多一点点 JS 开销(ShaderQuad 每次重填 4 个顶点、`ShaderQuad.js:279-309`)。可忽略。

**工程量**:**1-2 天**出可看的原型。这是验证"火焰底边不规则 / 持续自然 / 无帧感"这些**审美目标**最快的路,而审美目标恰恰是本项目最需要早验证的(制作哲学:点名 2 次 = 停下对齐)。

### 路径 ④:独立 WebGL canvas 叠加 + 每帧同步相机 —— ❌ 对本需求是死路

**可行性证据**(技术上能做):`scale/ScaleManager.js:162` `canvasBounds`、`:227` `displaySize`、`:265` `displayScale` 给你 CSS 对齐所需的一切;相机 `cameras/2d/BaseCamera.js:365` `matrix`、`:1326` `setScroll`、`:1433` `zoomX/zoomY` 可直接喂 uniform。状态污染风险为零(独立上下文)。

**为什么否掉**:
1. **深度排序彻底丧失**——这是致命伤。叠加 canvas 只能整体在游戏画面之上或之下。你的需求写着"能被场景固体挡住";sim 内部的障碍边界能解决"火不穿墙",但**前景层(走廊天花板、前景道具、玩家)永远无法压在火焰之上**。项目的"立体视觉结构/所见即所碰"哲学下,这个会立刻被看出来。
2. **合成方式受限**:要做加色发光只能靠 CSS `mix-blend-mode`(浏览器实现不一、开销高、在合成层上容易触发额外的离屏 pass),或退化成普通 alpha 混合 → 丢掉火焰该有的过曝感。
3. 第二个 WebGL 上下文占显存,浏览器活跃上下文有上限(常见 8-16),低端机上有被驱逐的风险。
4. FIT 缩放 + `autoCenter` 下,两个 canvas 的亚像素对齐在窗口尺寸变化时容易漂移。

**工程量**:1-2 天,但会撞死在第 1 条上,不建议投入。

### 4.1 半浮点场纹理(唯一需要裸 GL 的地方)

```js
function makeHalfFloatTexture (renderer, w, h) {
  const gl = renderer.gl
  const tex = renderer.createTexture2D(          // WebGLRenderer.js:1750,自动进 glTextureWrappers
    0, gl.LINEAR, gl.LINEAR, gl.CLAMP_TO_EDGE, gl.CLAMP_TO_EDGE,
    gl.RGBA, null, w, h, /*pma*/false, /*forceSize*/true, /*flipY*/false)

  tex._processTexture = function () {
    renderer.glTextureUnits.bind(this, 0)       // 走缓存,不打脏(WebGLTextureUnitsWrapper.js:112)
    gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, this.minFilter)
    gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, this.magFilter)
    gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, this.wrapS)
    gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_T, this.wrapT)
    gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA16F, this.width, this.height, 0, gl.RGBA, gl.HALF_FLOAT, null)
  }
  tex._processTexture()                          // 立刻重新分配为 16F
  return tex
}
```

```js
      .setDepth(DEPTH_FX)
    this.acc = 0

  // 流体的扩散/浮力速率必须按固定 dt 推进,否则高刷下火焰"变慢/变快"。
  step (deltaMs) {
    this.acc += deltaMs
    const DT = 1000 / 60
    let sub = 0
    while (this.acc >= DT && sub++ < 3) { this.simulate(DT / 1000); this.acc -= DT }
  }

  simulate (dt) {
    const U = { dt, texel: [1/this.w, 1/this.h] }
    advectVel .run(this.vel[1], [this.vel[0].texture, this.obstacle], U); swap(this.vel)
    advectDye .run(this.dye[1], [this.vel[0].texture, this.dye[0].texture, this.obstacle], U); swap(this.dye)
    forces    .run(this.vel[1], [this.vel[0].texture, this.dye[0].texture], {...U, buoyancy, vorticity}); swap(this.vel)
    divergence.run(this.div,    [this.vel[0].texture, this.obstacle], U)
    for (let i = 0; i < JACOBI_N; i++) {                 // JACOBI_N ≤ 20,CPU draw call 是瓶颈
      jacobi.run(this.prs[1], [this.prs[0].texture, this.div.texture, this.obstacle], U); swap(this.prs)
    }
    gradSub   .run(this.vel[1], [this.vel[0].texture, this.prs[0].texture, this.obstacle], U); swap(this.vel)
    shade     .run(this.out,    [this.dye[0].texture], { rampLUT })   // 温度→火焰配色
  }

  inject (worldX, worldY, radius, temp, fuel, impulse) { /* 一次 splat pass,爆炸时调用 */ }
}
```

## 五、务必写进 skill 的坑清单

1. **`type: Phaser.AUTO` + 自带 canvas = 直接抛错**(`core/CreateRenderer.js:34`)。传 canvas 必须写 `Phaser.WEBGL`。
2. **`config.context` 必须和 `config.canvas` 成对传**,否则上下文属于另一张 canvas。
3. **Phaser 一切离屏目标都是 RGBA8**(`DrawingContext.js:305` + `WebGLTextureWrapper.js:416`)。要浮点只能覆盖 `_processTexture`。
4. **FBO 纹理是上下颠倒的**(`BaseFilterShader.js:24-34` 官方说明)。显示时 `setFlipY(true)`,或在着色器里翻 V。
5. **`DrawingContext` 默认 autoClear 开**(`:135`),ping-pong 前必须 `setAutoClear(false,false,false)`。
6. **`beginDraw()` 是非 force 更新**(`:715`)。任何未经 `glWrapper` 的裸 GL 状态改动都会导致下一次绘制静默走错状态。
7. **`RebindContext.run` 开头会 `gl.clear(DEPTH_BUFFER_BIT)`**(`RebindContext.js:75-79`),作用于当时绑定的 FBO —— 返回前绑好正确的目标。
8. **绑纹理一律用 `renderer.glTextureUnits.bind(tex, unit)`**,不要 `gl.bindTexture`(单元缓存在 `WebGLTextureUnitsWrapper.js:112`)。
9. **不被 Phaser 追踪的状态**:`depthMask/depthFunc`、`cullFace(mode)`、`frontFace`、`lineWidth`、`pixelStorei(UNPACK_ALIGNMENT)` —— 动了自己还原。
10. **所有 GPU 资源用 `renderer.createXxx` 创建**(而非裸 `gl.createXxx`),才能进 `glTextureWrappers/glFramebufferWrappers/glProgramWrappers/glVAOWrappers`,享受上下文丢失自动重建(`WebGLRenderer.js:1048-1056`)。
11. **固定步长子步**:流体必须按固定 dt 推进并限制每帧子步数(≤3),否则 165Hz 实机上火焰速率与 60fps 完全不同 —— 与项目现有的"按时间归一化"纪律同源。
12. **障碍 mask 更新时机**:关卡 solids 是矩形列表,CPU 端光栅化进 `Uint8Array` 再 `textures.addUint8Array`(`TextureManager.js:1230`)只在关卡加载/门开合时更新,不要每帧重传。
